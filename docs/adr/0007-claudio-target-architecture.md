# 以 Claudio 施工图作为最终产品架构

日期：2026-09-20。状态：**接受为目标；代码迁移尚未执行**。

## 背景

用户明确确认 [Claudio 施工图](../architecture/claudio-target.png) 仍是最终目标，要求严格按图规划后续方向和功能。现有代码已完成音乐、自动选歌/补歌和 DJ 核心，但缺少用户语料、统一上下文、生活信息、节律调度、聊天、PWA 和音响等能力；部分现有选型与图不一致。

## 决定

1. 以 [开发路线图](../plans/2026-09-20-claudio-roadmap.md) 的 A01–D06 映射作为完整范围，按 P0–P8 交付；每项分别记录实现与验收，不能把替身通过当作真实服务完成。
2. 最终默认大脑是本机 Claude Code 子进程，使用已登录订阅路径，输出 `{say, play[], reason, segue}`；现有 Codex 在迁移期可显式回退，不是目标替代品。迁移选歌和 DJ 两条路径，补齐流式聊天。实际 CLI 参数以官方有效语法为准。
3. 最终核心实时合同是 `WS /stream`，支持聊天增量及 now-playing/任务状态；现有 SSE 逐步迁移。六条图示接口全部实现，必要的登录、反馈、音频等辅助路由保留。
4. 建立四份 user 文件、`prompts/dj-persona.md`、六片统一上下文与 messages/plays/plan/prefs 持久化。默认数据目标是 `state.db`、`cache/tts/`，媒体入口为 `/tts/<hash>.mp3`，PWA 构建入口为 `localhost:8080`；保留已有显式配置并迁移旧数据。
5. 实现图示 07:00 规划、09:00 早间、每小时情绪检查和日历 hook；天气、所选飞书日历与 UPnP/Naim 均在最终范围。定时触发准备，不等于未获用户开播意图即可出声。
6. 保留 React/TypeScript/Vite、NestJS、SQLite。图中 `.js` 文件名映射为模块职责，不回退工程语言或框架；不为图中的六个框复制第二套现有控制器。
7. 保留浏览器队列与播放决定权。now/next 是客户端实际观察的投影；模型、调度、WS 不能自行推进播放。Naim 作为受当前浏览器意图控制的唯一输出设备，服务端代理命令和回读状态；网页关闭后独立继续调度不属于本目标的默认解释。
8. 保留实际播放幂等记账、50/50 自动选歌、不喜欢具体版本排除以及暂停/停止后旧结果失效。新增聊天、定时、日历和设备入口也必须满足这些约束。

## 影响与验收

新增能力按接口和状态归属实施；共享结构在 contracts 维护运行时校验。先准备用户资料和数据基础，再统一大脑与上下文，然后接环境、调度、聊天、PWA 和音响。

实施 Claude/WS/路径迁移时分别保留可回读的数据与协议兼容，禁止仅改默认路径导致空库，或同时启用两套实时消费而重复入队。完成标准包含完整两小时收听、跨日调度，以及 Naim 实机证据；详细出口见路线图 §9–§11。

本 ADR 记录最终方向，不声称新增模块已经存在，也不执行供应商、端口、数据库或调度切换。
