# 编排层：队列留在网页端，服务端只负责准备下一批

自动补歌需要协调「队列、生成、播放意图、失败恢复」，但播放器只有一个网页 `<audio>`，且浏览器要求用户手势才能出声。决定：**播放队列与播放意图代次留在网页端（现为 `apps/web/src/orchestration/refill-controller.ts` + `apps/web/src/app/radio-context.tsx`，迁移前是 `public/orchestrator.js` + `public/app.js`），服务端只负责准备下一批可播内容（现为 `apps/api/src/preparation/orchestrator.service.ts`，迁移前是 `server/orchestrator.js`）**，不把队列搬到服务端，也不新增第二套播放调度。ADR-0004 的技术栈迁移不改变本决定。

服务端的职责被限制为：按会话与意图代次去重生成、调用 Codex、做可播性二次校验、失败时降级用曲库候选、给 Codex 记退避冷却、以及让已经停止的会话结果作废。网页端的职责是：决定何时补歌、只追加不替换、按代次丢弃迟到结果、暂停不出声、队列末尾等待下一批。

## Considered Options

- **服务端持有队列并推送播放指令**：单一事实来源，但浏览器手势、`<audio>` 状态、失败重试都要跨进程来回，等于重做一遍已通过验证的播放器竞态处理；本轮范围不需要。
- **整个补歌逻辑都放网页端**：实现最少，但多标签页或页面重连会重复生成同一批，且停止后的结果只能靠客户端自觉丢弃，缺少服务端兜底。
- **客户端队列 + 服务端协调（采用）**：改动面最小，复用既有播放意图代次机制；三层去重（客户端在途标志、服务端 sessionId+epoch Promise 复用、结果 id 去重）保证不会重复生成；服务端 `invalidateSession` 给停止会话兜底。

## Consequences

- 队列不是服务端持久状态：网页刷新后不恢复队列，需要重新开播；这符合规格「刷新不自动出声、不创建重复播放任务」。
- 若将来要支持多设备接续收听，需要把队列提升为服务端状态，届时网页端控制器可退化为纯渲染层。
- 队列条目统一带 `type` 字段；当前只有 `track`，非 track 类型会被明确跳过并提示未实现，为后续「歌曲与播报统一编排」保留位置，但不把未实现能力写成已完成。
- 补歌的去重范围与发送给服务端的排除范围必须是同一个集合（当前曲＋待播＋已失败），不含已播历史：否则完整曲库播到末尾时，服务端返回的候选会被前端全部过滤成「补充 0 首」然后停止。已播曲目可以重新入队，短时间重复靠 45 分钟降权缓解，而不是靠过滤。
- 会话最新意图代次与在途任务分开保存：任务完成只释放在途状态，不清除最新代次；更旧请求在生成前拒绝，相同代次仍可生成后续批次。会话结束才清理最新代次。
- 默认参数（阈值 2、批量 5、退避 30s→5min、Codex 冷却 1→15min）按真实 Codex 的 ~15s／~2.28 万 token 与 3～5 分钟歌曲时长选取，细节见 [验证报告第 10 节](../../.scratch/radio-agent/verification/report.md)。

## 2026-09-20：DJ 请求顺序与会话恢复

`epoch` 仍是整个编排版本，补歌和 DJ 使用同一个值。串场的 `transitionId` 只标识身份；新增必填的非负安全整数 `transitionSeq`，由浏览器串场控制器每次打开新机会递增，同机会重试复用序号和身份。服务端按 `(epoch, transitionSeq)` 比较请求顺序，相同顺序必须携带相同身份、前后条目、目标歌曲及文案上下文，否则返回冲突。

准备流水线通过注入的会话接口核验当前开放会话，先验会话与顺序、再查重复任务、最后调用供应商。每个异步阶段结束都再次核验当前会话和顺序；停止后的请求不能启动，迟到结果不能进入下一阶段或发布为 ready。任务状态仅由 JobStore 持有，顺序记录独立于任务保留期。

SQLite 会话记录增加 `highest_epoch`（旧库默认 0）、`transition_seq`（默认 -1，表示没有 DJ 机会）和规范化请求内容。补歌接受更高版本时同步推进 `highest_epoch` 并重置机会序号；任务完成或回收不会清空这些字段。会话结束后保留记录用于拒绝重放；进程重建仍可读取最高顺序。实际服务启动仍沿用关闭遗留开放会话的策略，不代表重启后会自动继续收听。

页面刷新仍不恢复队列或自动出声。用户再次开播时先取得复用开放会话的快照，将本地补歌和 DJ 的共同版本推进到大于服务端 `highest_epoch`，再允许准备；同一控制器的重连不重置已发出的机会序号。

## 2026-09-20：来源选择收口

`SourceSelection` 由浏览器运行时装配，歌单加载与 Codex 主动选歌共用 `RefillController.epoch`；停止、来源替换或后来的选歌操作都会使旧成功/失败响应失效。组件生命周期结束也不再接纳它发出的请求结果。组件仅展示资料和发出命令，不直接修改队列条目的自动记账属性；手动点播通过播放器命令清除自动选择标识。初始化曲库只在原意图仍有效且队列为空时应用，不覆盖已生效的用户操作。
