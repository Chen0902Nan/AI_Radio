# 音乐接入用社区维护的接口，不走官方开放平台

规格原本把官方网易云 CLI 列为资料读取的优先候选。实测后决定：音乐资料读取与音源都继续用社区维护的 `@neteasecloudmusicapienhanced/api`，不迁移到官方开放平台。

原因是官方在「个人」这条线上拿不到播放器最需要的东西。用真实 appId + privateKey 自建签名客户端（不经过 CLI）调用官方接口，同一张匿名令牌下的对照结果很干净：查询歌曲、歌单详情、歌曲详情、用户信息返回 `301 用户未授权当前接口`，说明应用本身已授权、只缺用户登录；而获取歌曲播放 url 的两个接口返回 `300 应用未授权当前接口`，是应用层级就没有权限，换用户令牌也不会变。另外 `device` 里的 `channel` / `deviceType` / `os` 由云音乐线下分配，官方 CLI 能用是因为它带着被授权的 `ncmcli` 通道身份，不是因为 appId 拿到了这些权限。

## Considered Options

- **个人入驻 + 自建客户端**：唯一一路验证到接口层的选项，取音源不可用，排除。
- **个人入驻 + 用官方 CLI**：CLI 能读资料也能播放，但播放由 mpv 承担，网页播放器用不上；且它的动态命令清单在本机始终为空。
- **厂商入驻**：文档明确「仅支持企业入驻，不支持个人开发者」，并写明「本平台音乐服务不是免费提供」，与个人自用项目不匹配，排除。

## Consequences

- 稳定性与合规性风险由本项目自担：社区接口随时可能被改协议或封禁，官方没有任何承诺。
- 音乐接入收敛在 `server/netease.js` 一层；将来若官方开放取音源权限，替换范围限于这一层。
- 官方 CLI 仍可用于人工听歌，与本项目互不影响。

实测细节与完整接口矩阵见 [开放平台调研](../../.scratch/radio-agent/open-platform-research.md)。
