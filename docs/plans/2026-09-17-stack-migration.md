## 1. 结论

项目已经从音乐链路原型推进到“真实歌曲播放 + Codex 选歌 + 自动补歌 + 会话/反馈 + DJ 串场”。不能再沿用此前“自动补歌、DJ、Fish 都未实现”的进度判断。

当前适合做保行为的架构迁移：把已有播放能力搬入清楚的模块，先保证已有行为不退化，再继续天气、日历、聊天和每日准备。迁移不承诺同步完成所有产品功能，也不把框架启动成功当作播放器验收通过。

关键约束：遵循 [ADR-0003](../adr/0003-orchestration-queue-ownership.md)，**节目队列和播放决定继续由浏览器持有，服务端准备内容并协调任务**。此前讨论过服务端持有队列的方向，但它与当前正式 ADR 不一致，本文不采用。引入 NestJS 或 SSE 不构成更改队列归属的理由。

## 3. 目标技术栈与选型

| 层次 | 决定 | 原因及限制 |
| --- | --- | --- |
| 仓库 | 保留 npm，使用 npm workspaces | 前端、后端、共享契约分别构建；一个 lockfile，不同时更换包管理器 |
| 前端 | React + TypeScript + Vite | 组织播放器、队列、资料、DJ 来源和音色设置；页面组件不直接承担音频调度 |
| 样式 | Tailwind CSS，使用 Vite 插件 | 将现有样式逐组件迁移，保留 CSS 变量作为主题值；复杂动画可有少量普通 CSS |
| 后端 | NestJS + TypeScript，默认 Express adapter | 模块与依赖注入适合现有接入层；本次不叠加 Fastify adapter 迁移 |
| 数据库 | SQLite，保留 `node:sqlite` | 保留表和数据，优先隔离数据访问，不引入 ORM 和数据格式迁移 |
| 运行时 | 固定经过验证的 Node 版本 | 必须同时支持 node:sqlite、env 文件与现有代理启动选项；以锁定版本的实测为准 |
| 契约 | 共享 TypeScript 类型 + 现有运行时校验逐步类型化 | 不另建一套与 `program-contract.js` 不一致的 DJ 定义；外部输入必须校验 |
| 通信 | HTTP 保留现有接口，增加 SSE 任务状态通知 | SSE 不发强制播放命令，不成为队列事实来源 |
| 播放 | 独立 TS PlaybackController，单一 audio | 音频生命周期独立于 React 渲染，保留旧媒体事件过滤 |
| 测试 | 先保留 node:test + Puppeteer；React 层按需使用 Vitest/Testing Library | 不同时重写已有 100 多项测试；TS 核心可先编译再交给 node:test |

具体依赖版本在 M0 查询官方兼容要求后锁定，不使用未验证的最新版本组合。安装后 `npm ci`、类型检查、构建和测试必须可重复；Vite 转译不代替 `tsc --noEmit`。

NestJS ValidationPipe 可用于简单 DTO；复杂节目请求优先用自定义 Pipe 调用共享校验器。无论采用哪一种，不保留两份相互竞争的业务校验。错误码和字段兼容已有接口，不能通过框架默认异常格式悄悄改变合同。

## 4. 目标结构与职责

```text
apps/
  web/
    src/
      app/                   # 页面入口、应用装配
      features/              # 播放器、资料、反馈、DJ、音色设置
      playback/              # PlaybackController、媒体归属、节目队列
      orchestration/         # RefillController、SegueController
      api/                   # HTTP 与 SSE，运行时校验

  api/
    src/
      main.ts
      app.module.ts
      config/                # 明确数据路径、环境、代理及服务配置
      persistence/           # SQLite、settings、feedback、sessions、plays
      music/                 # 网易云资料、音源与流转发
      codex/                 # 子进程执行及结构化结果
      preparation/           # 补歌协调、候选抽样、降级/冷却
      dj/                    # 写稿、Fish、缓存、任务查询和取消
      listening/             # 会话及停止时统一作废任务
      events/                # SSE 订阅与状态通知
      test-support/          # 仅显式测试模式注册

  contracts/                 # 共享纯类型、校验器、错误码；无 Node/React 依赖
```

模块导出少量业务操作，不为每个函数生成一层转发 Service。只有需要替换的外部依赖提供接口，例如 Codex 执行、语音合成、音乐查询、时钟和存储；避免所有内部对象都变成公共接口。

依赖方向：Controller → 业务模块 → 外部接入/存储。`Listening` 停止会话时调用准备与 DJ 的作废接口；底层模块不反向导入 Controller，也不依赖浏览器代码。共享契约不能引入服务器密钥处理或文件系统代码。

## 5. 迁移必须保持的行为合同

### 5.1 播放与身份

必须分别保留 `sessionId`、`epoch`、`itemId`、`trackId`、`transitionId`、`segueId`、`playInstanceId`、`playToken` 和试听代次。不得因为改成 TS 就把它们合并为一个数字，尤其不能拿歌曲 ID 判断某次媒体事件归属。

- 网页持有节目队列；刷新不恢复队列或自动出声，按现有会话行为重新连接。
- 开播由用户触发。React mount、SSE 重连、后台补歌完成不得触发自动开播。
- 一个应用实例只创建一个音频控制器；以入口装配和明确 dispose 管理生命周期。StrictMode 的开发期重复装配不能重复绑定事件、生成任务或写播放记录。
- React 用订阅快照（例如 useSyncExternalStore）显示控制器状态；组件不直接调用 audio.play 或维护第二份可变队列。
- 旧媒体的 playing/ended/error 不能记到新播放实例；暂停恢复不重复写记录。
- 暂停后的迟到生成结果可以保留，但不能出声；停止作废任务和机会，随后重开新会话。保留当前已确认的“停止后重开可从原歌曲位置继续”行为。
- 去重范围为当前曲、待播曲和失败曲；已播历史允许重新入队，短时重复通过权重降低，不能过滤整段历史导致队尾无法续播。
- DJ 只按有效歌曲自然结束计数，跳歌与 DJ ended 不累计；结束决策关闭后，迟到串场不能插播。
- 试听与正式节目共享唯一音频出口但身份独立；开播、停止和切歌使不再适用的试听结果失效。

多标签页目前没有完整验收；迁移只承诺单活动播放页。不得用 SSE 广播让所有标签页同时播放；多页独占/接续需要单独需求与 ADR。

### 5.2 HTTP 与 SSE

M0 记录现有路由的方法、状态码、字段、错误体与副作用，特别是部分旧路由没有严格方法限制的情况；不能只记录 URL。M2 保留客户端实际依赖的调用方式。

重点接口：`/api/login/*`、`/api/library`、`/api/playlist/:id`、`/api/resolve/:id`、`/api/audio/:id`、`/api/plan`、`/api/queue/refill`、`/api/session*`、`/api/feedback*`、`/api/settings`、`/api/plays/*`、`/api/dj/*`。

NestJS POST 默认状态码与旧服务可能不同，应显式声明兼容响应。音频不能被统一 JSON 包装；保留 Range、206/416、长度和类型，客户端断开时停止上游读取并释放资源。音频与 SSE 排除压缩/缓冲等会破坏流行为的全局处理。

SSE 在 M4 单独引入：

- 提议新接口 `GET /api/events`，仅通知服务端准备任务和配置状态；消息含协议版本、sessionId、epoch、任务身份和序号。
- 首次/重连查询当前会话及相关任务快照；事件仅作通知，丢失或重复事件不改变播放语义。未知或过期会话/任务消息直接忽略。
- 无持久事件重放时明确采用“重连拉快照”，不假装 Last-Event-ID 可恢复全部历史。
- 首阶段补歌仍以原 POST 响应交付批次；SSE 不能同时再追加同一批歌曲。
- 用 SSE 更新 DJ 状态后，保留有界轮询作为断线降级，并使用同一处理入口去重；连接恢复后停止备用轮询。
- 断开订阅释放心跳、监听与 RxJS subscription；断线不等于停止会话，取消任务仍走明确命令。

### 5.3 数据、配置与构建

- 从 `__dirname` 相对路径改为集中配置的绝对数据目录；编译到 dist 后仍指向既有根目录 data，不得默默创建空库或丢失登录态。
- 保留 `RADIO_DB_FILE`、`DJ_AUDIO_CACHE_DIR` 和现有凭据/代理配置的覆盖方式。显式加载根目录 .env；前端仅允许公开配置，不打包任何外部密钥。
- Nest bootstrap 中统一初始化数据库、收尾旧会话；Controller 导入不得打开数据库。测试启动不得连接真实库；不能让新旧服务同时对真实库执行启动收尾。
- M2 不改 schema。若确有后续迁移需求，使用版本化、事务化迁移；SQLite WAL 场景下用一致性备份方式，不能只复制正在写入的 db 主文件。
- Codex/Fish 参数、代理支持、超时、缓存键和淘汰策略保持。音频缓存只能移入废纸篓，测试清理同样遵守；不自动清空废纸篓。
- contracts 提供 browser ESM 和 Node 可消费产物，用 package exports 明确入口；API 初期保留 CommonJS 编译以兼容依赖，web 使用 ESM。必须实际验证构建后的导入，不用全局改 type=module 强行混用。
- 开发：Vite 将 `/api` 代理到 Nest，包括音频及 SSE。生产：Nest 提供 Vite 构建产物，API/音频请求不落入 SPA fallback；保持单一本机入口和默认回环监听。

## 6. 实施分期与退出条件

按 M0 → M1 → M2 → M3 → M4 → M5 推进。每阶段可形成独立可审查改动；提交/推送遵循用户指令，不默认执行。

### M0：冻结基线与可重复验证

输入：本文指定 commit 与现场新增改动。若已有其他 Agent 修改，先核对新基线。

产出：路由合同清单、数据/配置路径清单、基线验证报告、固定 Node/依赖版本；修正旧测试永久删除临时目录的清理方式。为真实链路验证使用独立端口、数据库和音频缓存，不重启用户现有实例。

退出：现有离线全套通过；明确历史/本次、真实/替身、跳过项。更新记录指针和迁移 ADR，说明保留 ADR-0003。未获得真实服务条件不伪造通过，可继续不依赖它的迁移工作。

### M1：工程骨架与共享 TypeScript 契约

建立 workspaces、web/api/contracts 构建和独立类型检查。先将 program-contract 及纯函数迁入共享包，使用现有测试证明转换前后有效/无效输入行为一致；补齐 HTTP DTO 类型，避免 any 扩散。

新目录可以分步接入 JS，但过渡文件必须有明确清单和移除阶段；最终核心业务不能仅把 JS 包装进 Nest Service 而宣称 TS 迁移完成。

退出：旧应用仍可启动；共享包在 Node 和 Vite 中均可导入，原契约测试通过，无服务端模块进入浏览器包。

### M2：先迁后端，旧网页验证新 Nest 服务

按 Persistence/Config → Music/Codex → Preparation/DJ → Listening/Controllers 顺序迁入。临时适配只用于缩小单次改动，迁移完成后旧新路由不同时掌握同一任务状态。

用旧网页连接新 Nest 服务验证接口兼容，先保持 DJ 查询方式，不同时改 SSE。补齐音频流、取消、状态码和生命周期回归。

退出：旧网页在新后端完成登录资料读取、播放、补歌、会话反馈及 DJ 注入串播；数据库设置与反馈在前后版本读出一致；Range 与流中断检查通过。真实服务条件允许时补一轮自然跨批验证，尚未补证则不能宣称整体迁移已验收。

### M3：React + Tailwind 与独立播放控制器

先抽离 `public/app.js` 的媒体执行与状态，再逐组件替换 UI：登录/资料 → 播放器/队列 → 反馈/会话 → DJ 来源/音色设置。

迁移保留现有布局与交互，不同时大改产品视觉；Tailwind 类名完整枚举，避免运行时拼接导致构建漏样式。React 只订阅和发命令，补歌、串场控制器通过依赖注入接入播放控制器。错误提示、可点击来源、音色保存失败提示和禁用态全部保留。

退出：开发 StrictMode 与生产构建均无重复音频实例或任务；停/播/切歌/试听/反馈行为不退化，浏览器回归观察实际媒体进度，不能只断言歌名变化或 paused=false。

### M4：增加 SSE 状态通知

落实第 5.2 节的消息合同，DJ 状态通过推送及时更新，断线后查询快照恢复。补歌批次仍保留明确的唯一交付方式。

退出：断线、重复/乱序事件、会话切换、服务重启、旧事件到达都不重复入队或出声；SSE 不可用时音乐继续，轮询有界且恢复后清理；长期连接资源能释放。

### M5：完整迁移验收与清理

使用构建产物从单一入口启动，完成类型检查、构建、离线测试、相关既有回归与实际跨批/串播证据。保留回滚入口至验收通过，之后将废弃代码及本次无用临时文件移入废纸篓，避免两套生产实现并存。

产出：启动说明、环境模板、迁移 ADR、文件映射、验证报告、剩余产品任务及最新状态索引。更新 package 描述，避免仍写“第一阶段音乐链路”。

退出：没有生产旧 JS 播放器/HTTP 路由并行运行；TS 核心不靠全局关闭严格检查通过；文档可让另一位开发者安装、构建和验证。

## 7. 验收矩阵

| 验收 | 方法 | 通过条件 |
| --- | --- | --- |
| 工程 | 安装、typecheck、build | 锁定依赖可复现，web/api/contracts 均成功 |
| 契约 | 现有样例+无效输入 | 数据归一化、错误码、字段与已有客户端兼容 |
| 媒体身份 | 确定顺序的加载/事件回归 | 旧 playing/ended/error 不误记、不跳歌，同曲重播也能区分 |
| 补歌 | 并发、旧 epoch、耗尽、降级 | 同意图不重复生成，最新意图水位保留，候选恢复后真实续播 |
| 自然跨批 | 真实曲从头自然结束 | 记录正常速度、无 seek、墙钟、loadedId 与新曲实际进度增长 |
| DJ 边界 | 注入浏览器 + 真实路径分别记录 | 自然结束计数正确、机会关闭不补插、暂停停止无意外出声 |
| 真实串播 | Codex+Fish+真实歌曲 | 实际歌曲→DJ→歌曲，记录真实音频时长和前进；加速前置曲目必须明示 |
| 试听 | 慢响应/切歌/停止/换音色 | 旧试听不接管节目，试听不污染正式播放计数及反馈 |
| 数据 | 独立库副本前后对照 | 设置/音色/反馈历史不丢失，启动目录变化不打开错误数据库 |
| SSE | 断网、重连、重复与乱序 | 快照恢复，无重复任务、队列追加或自动开播 |
| 持续运行 | 两小时现有功能稳定性 | 正常速度、无意外停止、失败行为有界；DJ 机会、生成次数与错误可回溯 |

最后一项是迁移后现有音乐/DJ能力的稳定性验收；即使通过，也不等于完成原规格包含天气、日历和聊天的两小时完整产品验收。真实服务暂不可用时，将该项明确列为待验收，不用模拟时间冒充两小时。

验证脚本应尽量保留原命令；因目录变化只改启动/导入/选择器适配，不降低断言。测试钩子保持显式开关，正常启动不能注册可修改测试状态的路由。

## 8. 风险、回退与范围控制

| 风险 | 控制措施 | 回退方式 |
| --- | --- | --- |
| React 重装导致重复播放 | 控制器唯一实例、订阅清理、StrictMode 回归 | M3 期间同一后端切回旧网页；一次只启用一套播放器 |
| Nest 改变流/异常语义 | 旧网页先验、显式状态码、流专项验证 | M2 失败恢复旧服务入口，停止新实例后再接真实数据 |
| 编译输出改变数据目录 | 统一绝对路径，副本验证 | 不改 schema，恢复旧入口和原数据路径 |
| 类型迁移掩盖运行时校验 | unknown 输入先校验，旧合同测试不删 | 保留适配入口至全部调用迁移完成 |
| SSE 重复或漏通知 | 幂等处理、快照恢复、单一批次交付 | 退回原查询方式，不退回播放身份修复 |
| Codex/Fish 外部条件变化 | 锁定调用配置、生成失败继续音乐 | 保留已有有界降级；不切换新增付费服务 |

原有数据库优先不做破坏性迁移；如果后续确需改表，单独安排备份和回滚演练。回退代码不应覆盖迁移期间新写入的真实用户反馈。

本方案只授权为本次文档提供实现指导，不代表已经执行安装、重构、外部调用或发布。执行时不得擅自将音乐接入换回官方平台，或把队列搬到服务端。

## 9. 迁移完成后的产品顺序

1. 将收藏歌单纳入自动候选，再实现歌单外探索及比例目标。
2. 接天气与所选飞书日历，完成开场分段、失败补播和当天完成记录。
3. 实现文字聊天的明确点歌与会话临时调整，复用 epoch/机会作废机制。
4. 每日节目准备使用 Nest 定时能力与 SQLite 完成记录；启动/恢复后检查遗漏，准备不出声。
5. 做涵盖开场、DJ、反馈、聊天的两小时完整验收。

以上不是本次迁移退出条件，不提前创建无业务内容的 Weather/Calendar/Chat 模块。
