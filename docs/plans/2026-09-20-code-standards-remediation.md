### T1：恢复播放的旧错误不得归到新歌曲

**范围**：[playback-controller.ts](../../apps/web/src/playback/playback-controller.ts) 的 `resume()`、[播放测试](../../apps/web/test/playback-controller.test.mts)、[运行时测试](../../apps/web/test/radio-runtime.test.cts)。

保存本次恢复的播放代次和曲目身份；`audio.play()` 成功或失败后都确认仍属于当前操作。复用现有代次机制，错误归属不能读取已经变更的当前歌曲。

**验收**：恢复 A → 切 B → A 拒绝，不得把 B 标失败、结束 B 的记录或取消 B 的串场；恢复后停止、暂停的迟到拒绝也无副作用；当前恢复真实失败仍有提示。普通暂停恢复不重复记账。

### T2：统一 DJ 设置归属，隔离每次音色试听

**范围**：[DjPanel.tsx](../../apps/web/src/features/dj/DjPanel.tsx)、[radio-context.tsx](../../apps/web/src/app/radio-context.tsx) 的设置同步、串场配置入口。新增设置/试听控制模块放在前端编排目录，具体文件名随职责确定。

设置读取、保存、服务端事件同步和应用到串场控制器收敛到同一入口；组件只保存表单草稿，已生效配置由该入口管理。读取记录本地修改版本，旧读取不能回滚新操作；快速连续保存按序处理或合并，失败后恢复已确认状态并提示。音色试听增加独立请求代次，编辑音色、再次试听、开始收听、停止试听或离开页面均使旧请求失效；仅当前已试听成功的音色可保存。

**验收**：关闭 DJ 后旧 GET 返回不能重新开启；连续切换设置、SSE 通知乱序后最终页面、控制器与服务端一致；A/B 试听乱序只播 B；合成期间开播又停止，旧试听仍不得恢复；试听 A 后改填 B 不能沿用 A 的成功状态保存 B；保存失败可见且不留下错误的生效状态。设置同步不打断已经出声的歌曲或 DJ。

**测试入口**：编排模块公开命令/快照测试，加浏览器按钮、设置和媒体结果测试；不以组件内部 `setState` 调用次数作为通过条件。

### T3：登录页请求与计时器共用一个生命周期

**范围**：[LoginPage.tsx](../../apps/web/src/features/login/LoginPage.tsx)、[登录浏览器用例](../../scripts/browser/login.test.mts)。

每轮二维码生成使用独立代次和取消信号。新一轮或卸载时取消旧请求，清理轮询、过期刷新和成功跳转计时器；每次返回先校验代次。轮询完成后再安排下一次，避免慢响应造成重叠。

**验收**：连续刷新、响应乱序、卸载后返回都不能覆盖新二维码或重建计时器；StrictMode 的建立→清理→建立只保留一轮有效轮询；旧轮询的成功/过期状态不能触发新一轮跳转/刷新。保留现有断网、空响应与重试提示。

### T4：DJ 服务端拒绝过期会话和乱序准备

**范围**：[dj-pipeline.service.ts](../../apps/api/src/dj/dj-pipeline.service.ts)、[dj.controller.ts](../../apps/api/src/dj/dj.controller.ts)、[listening.service.ts](../../apps/api/src/listening/listening.service.ts)、[SegueController](../../apps/web/src/orchestration/segue-controller.ts) 及共享准备契约。

准备入口先核对真实开放会话，再决定是否复用或替换任务；流水线通过显式依赖获得会话有效性，不依赖 HTTP 控制器。保留每个会话的最新请求顺序，旧请求在调用供应商前拒绝，任务结束不清除顺序记录，关闭会话后不能重新启动旧任务。

现有 `epoch` 表示编排版本，同一版本内有多个串场机会；`transitionId` 只表示身份，不能排序。新增 `transitionSeq` 到共享准备契约，由浏览器编排所有者生成，服务端按 `(epoch, transitionSeq)` 判断先后；同一机会重试复用身份与序号，相同顺序携带不同内容返回冲突。

重连复用控制器顺序；整页刷新保持现有“复用开放会话、不会自动播放”的语义，从服务端会话快照恢复最高已见版本后才允许新准备，并统一补歌与串场使用的 `epoch`。最高版本随会话持久保存，避免服务重启后接受旧请求；兼容已有数据库的初始化值。契约变更同步记录到 ADR 和接口文档，缺失顺序字段明确返回校验错误，前后端及测试同批更新。

**验收**：先新版本、后旧版本；同版本先新机会、后旧机会；最新任务完成后旧请求才到；重复请求幂等；同键不同内容冲突；不存在/已结束/不匹配会话均拒绝。停止后请求才到、停止发生在任一准备阶段，都不能发起后续供应商调用或把旧结果标为可用。页面刷新和服务重启后仍保持请求顺序，新会话不受旧会话记录影响。

**测试入口**：[流水线测试](../../scripts/tests/dj-pipeline.test.mts)、[串场控制器测试](../../scripts/tests/segue-controller.test.mts)，并增加使用临时数据库的真实 HTTP 准备入口测试，覆盖会话校验而不仅是底层工厂。

### T5：客户端断开时结束音频转发

**范围**：[music.controller.ts](../../apps/api/src/music/music.controller.ts) 的 `audio()`、[HTTP 测试](../../scripts/tests/migration-http.test.cts)。

为上游请求传入取消信号，客户端 `close/error` 后取消读取；等待背压恢复时同时处理关闭和错误。成功、失败、断开都进入统一清理路径，释放 reader 与事件监听器；连接关闭后不再写响应。可提取小型流转发模块，但保留 Range/206 和响应头语义。

**验收**：连接在上游返回前、读取中、等待 `drain` 时断开，处理都能结束，上游被取消且监听器不残留；正常完整传输、Range、上游错误维持原合同。至少一项使用本地 HTTP 流验证真实断开事件，不调用音乐 CDN。

### T6：把外部数据校验与类型承诺补齐

**范围**：[netease.service.ts](../../apps/api/src/music/netease.service.ts)、[前端 API 客户端](../../apps/web/src/api/client.ts)、[共享契约](../../packages/contracts/src/index.ts)、[测试装配](../../apps/web/test/support/runtime.cts)、[工具类型](../../scripts/lib/tool-types.d.ts)。

- 网易云响应作为 `unknown` 接收，按接口校验容器和实际使用字段；URL 必须为有效 HTTP(S) 字符串，ID/时长/到期参数为符合用途的有限数字，歌手列表为数组。无效音源不得标成完整可播；不完整曲库不得据此判定歌曲在歌单外。
- 前端共享请求/响应在契约包定义，由 API 边界解析；消除 `Promise<ResolveResult>` 的双重断言和各组件重复解释响应。非法 2xx 响应返回可识别错误，不能当作正常空数据。
- `validateQueueItem` 等校验器的成功结果必须满足声明类型；选择校验并规范化返回值，或明确拒绝错误类型，不能只检查转换后的数字却返回原字符串。旧结构统一走适配工厂，保留既有错误码语义。
- 为 CJS `require` 的生产模块、测试辅助函数与替身补显式类型，保留现有加载顺序；任意证据使用 `unknown`，第三方缺类型的适配局限在接入点。逐处说明保留 `any`/断言的依据，不追求无依据的清零。

**验收**：数字 URL、非法到期时间、非数组歌手、缺失必填字段、畸形 HTTP 数据被拒绝或明确降级；正常数据通过；校验成功后的字段实际类型与声明一致。错误的 fixture 参数类型会导致类型检查失败，测试不能通过未声明类型的加载链绕过约束。

**测试入口**：共享契约用例、网易云接入替身用例、前端 API 解析用例及 `npm run typecheck`。校验行为修复与契约文件拆分分别完成。

### T7：让验证工具对应当前页面，并可靠恢复环境

**范围**：`scripts/verify-*.mts`、[tool-types.d.ts](../../scripts/lib/tool-types.d.ts)、[运行命令](../../package.json)、[验证指南](../agents/verification.md)。

逐项盘点仍使用 `window.__radio` 和旧 DOM 选择器的脚本，对照当前浏览器测试迁移到可见交互、`data-radio-observation` 及带类型的测试适配；不为旧脚本重新暴露可任意改状态的生产全局对象。保留现有 npm 入口及场景覆盖，命令缺少前置条件时明确失败，不能跳过后报告通过。

会改变注入模式或配置的工具使用自建隔离服务：启动前绑定临时数据库、登录态、音频缓存及报告路径，不能只改端口。通过 `finally` 恢复修改过的状态、关闭浏览器和服务、处理临时目录；外部服务模式必须能记录并恢复原状态，否则在修改前拒绝该模式。DJ 冒烟包括文案/Fish 注入状态恢复，错误路径也执行清理。

**验收**：每个保留入口都有最小本地替身检查；故意在准备、浏览器、报告写入阶段抛错，清理仍生效；工具结束后没有残留注入模式、浏览器或轮询。隔离路径之外的原数据库与登录态不变。真实供应商验证单独记录，不作为此次离线完成条件。

### T8：按职责拆分大模块，逐项处理复杂函数

先固化 T1–T7 的回归，再分批处理下列模块；拆分时保持公开行为和入口不变。

| 模块 | 拆分方向 | 必须守住的边界 |
| --- | --- | --- |
| `radio-context.tsx` | React 适配与无 React 的运行时装配分开；播放记账、DJ 任务监听、设置同步各自管理生命周期 | 仍只有一个播放器；组件不直接修改音频或复制队列状态 |

| `contracts/src/index.ts` | 按队列/身份、串场、校验职责组织文件，根入口保留公开导出 | Node 与浏览器均可使用，CJS/ESM 输出与导出兼容，不引入框架 |
