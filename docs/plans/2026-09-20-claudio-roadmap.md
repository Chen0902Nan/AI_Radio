## 1. 最终产品与对图原则

交付一个在本机运行的个人 AI 电台：读取用户口味和作息，结合天气、飞书当日日程与收听历史规划节目，接受文字交流，通过音乐与 DJ 语音陪伴收听，并可切换到客厅 Naim 音响。

完整体验：07:00 准备当天节目 → 09:00 触发早间内容 → 用户开播后听天气、日程和歌曲 → 每小时及日历变化时调整后续安排 → 用户通过聊天点歌或调整氛围 → 歌曲间穿插有出处的介绍 → 反馈与实际播放成为下一次准备的依据。

- 图片里的四层、外部能力、四份用户文件、六块上下文、六条核心接口和 PWA 均有编号及交付阶段，不能以“同类能力”省略。
- **Claude Code 是最终默认大脑**；现有 Codex 是迁移起点。**WebSocket 是最终实时通道**；现有 SSE 是迁移起点。两处均要实际迁移，不能仅改文案。
- 07:00 / 09:00 / 每小时 / 日历 hook 按图进入范围，替代旧计划的每日 08:45 单次准备。
- 图中的 `router.js` 等是职责名称；继续使用 React + TypeScript + Vite / NestJS / SQLite，在 `.ts` 文件中实现这些职责，不恢复已退役的 JS 工程。
- 图里的 `state.db`、`cache/tts/*.mp3`、`/tts/<hash>.mp3`、`localhost:8080` 都列为目标路径或入口。迁移须保留已有数据和显式配置。
- 图片没有说明的执行细节在本文标为“规划解释”。它们用于让任务可实施，不冒充图片原文。

## 3. 四层如何落到现有工程

以下目录是计划落点，不表示目前已存在。模块对外只暴露自身负责的业务动作，供应商、文件和重试细节留在模块内部；同一状态不能由两层分别维护。

| 层 | 图中职责 | 计划落点 | 唯一负责的事情 |
| --- | --- | --- | --- |
| 外部上下文 | 用户四份文件 | `apps/api/src/profile/`、`user/` | 资料读取、校验、版本、同步及编辑；Profile 视图不直接访问文件 |
| 外部服务 | Music / Claude / Fish / Feishu / Weather / UPnP | 复用 `music/`、`dj/`，新增 `brain/`、`environment/`、`output/` | 将真实服务与本地替身转换为相同的业务结果 |
| 本地大脑 | router | `apps/api/src/intent/` | 识别命令类别、处理歧义，决定是否需要检索或模型 |
| 本地大脑 | context | `apps/api/src/context/` | 组装六片上下文，统一优先级、长度、时间与版本 |
| 本地大脑 | claude | `apps/api/src/brain/` | 启动/终止子进程，解析结构化终态与聊天增量 |
| 本地大脑 | scheduler | `apps/api/src/scheduling/` | 调度去重、补执行和触发记录；不调用播放命令 |
| 本地大脑 | tts | 扩展 `apps/api/src/dj/` 的语音职责 | 文字到可播放本地资产，正式内容与试听互斥 |
| 本地大脑 | state.db | 扩展 `apps/api/src/persistence/` | 消息、计划、实际播放、偏好、任务运行记录 |
| 运行时聚合 | 触发 → 六片 → 模型 → 准备 | 扩展 `preparation/` 并新增 `program/` | 统一节目准备入口，把模型建议校验为可交付内容 |
| 交互表层 | Player / Profile / Settings | `apps/web/src/features/` | 展示资料、发送意图、显示任务和实际播放状态 |
| 交互表层 | 队列、播放、设备 | 保留 `web/orchestration/`、`web/playback/` | 接纳仍然有效的结果，决定排队、切歌及出声 |
| 跨端合同 | HTTP / WS / 内容与状态 | `packages/contracts/` | 共享类型、协议版本和运行时校验 |

现有 `preparation/orchestrator.service.ts`、`discovery-selection.ts`、`dj/pipeline*.ts`、`playback-controller.ts` 继续承担已实现的职责。新增统一入口负责调度这些能力，不复制第二套选歌、播放或 DJ 状态机。

目标数据流：

```text
用户命令 / 07:00 / 09:00 / 每小时 / 日历事件
  → 意图分流（简单命令直接处理；需要模型的任务继续）
  → 六片上下文快照 → Claude Code → {say, play[], reason, segue}
  → 网易云完整音源确认 + Fish 合成 + 准备结果持久化
  → HTTP 结果 / WS 状态通知 → 浏览器核对当前意图 → 接入待播队列
  → 唯一输出：浏览器 audio 或所选 Naim
  → 实际播放观察与记账 → state.db → 后续检索记忆
```

## 4. 用户资料、记忆与节目计划

### 4.1 四份文件的内容和写入规则

| 文件 | 必须支持的内容 | 写入与优先级 |
| --- | --- | --- |
| `user/taste.md` | 喜欢的风格/歌手、回避内容、DJ 语言与表达偏好 | 用户编辑为明确偏好；模型可提出修改建议，不把单次聊天自动变成长期偏好 |
| `user/routines.md` | 时区、作息、工作/休息场景、允许的收听时段 | 调度读取结构化元数据，正文作为语料；非法时间不替换上次有效版本 |
| `user/playlists.json` | 账号 ID、红心/自建/收藏歌单及歌曲版本、同步时间、完整性 | 音乐模块负责同步；同步失败保留可用快照并标为陈旧，不写成空曲库 |
| `user/mood-rules.md` | 场景到音乐氛围、强度和播报频率的规则 | 当前明确指令高于默认规则；“这次少说话”只覆盖当前会话 |

Markdown 文件使用可校验的元数据加自由正文；四份文件以一个 `profileRevision` 组成一致快照。支持 UI 编辑、外部文件修改后的重新加载、并发版本冲突提示和回读。仅示例模板入 Git，真实用户文件在实施 P1 时加入忽略规则。`prompts/dj-persona.md` 是应用人设，单独版本化。

持久化分工：文件是四份语料的真相来源；数据库 `prefs` 是显式设置/反馈索引与带来源版本的查询投影，不建立另一份可独立覆盖文件的口味正文。保留 ADR-0005：不喜欢具体版本是自动推荐硬排除；手动点歌允许选择，喜欢不等于增加原曲重播。

### 4.2 SQLite 扩展与迁移

| 数据 | 用途与最少身份信息 |
| --- | --- |
| `messages` | 用户/助手消息、conversationId、requestId、终态、创建时间；未完成增量不得当完整回答检索 |
| `plays` | 复用首次实际播放、playInstanceId 幂等和自动来源；扩展输出设备及实际观察来源 |
| `plan` | 用户本地日期、时区、revision、资料/环境版本、节目分段、准备状态及生成原因 |
| `prefs` | 用户设置及有来源版本的偏好投影，复用已有 feedback/settings 资料并定义迁移映射 |
| `trigger_runs` | 调度/日历事件幂等键、dueAt、attempt、状态、产出计划版本及失败原因 |
| `broadcasts` | 开场/早间等播报的准备、入队、实际开始和完成记录；失败分段可重试 |

`sessions`、`selections` 和已有记录保留。消息、节目计划、待播队列、实际收听历史必须分开：生成、预取、入队和音响命令成功都不能算实际播放。

**没有收听会话也能准备计划。** 现有补歌/DJ 准备绑定开放会话，P2/P4 必须增加区分计划与会话的准备身份：计划任务绑定 `planId + revision`，收听任务继续绑定 `sessionId + epoch`（DJ 另含机会序号）。07:00 不能为了调用旧接口而创建假收听会话。开播时由浏览器显式接纳仍有效的计划内容并生成当前队列身份；重新核对歌曲可播性、反馈与来源，不能把旧计划身份直接当播放实例。长期计划保存歌曲版本和内容资产引用，不把易过期的歌曲 URL 当作全天有效音源。

路径迁移目标是根目录 `state.db` 与 `cache/tts/`。存在 `RADIO_DB_FILE`、`DJ_AUDIO_CACHE_DIR` 等显式覆盖时继续使用；未覆盖的旧 `data/radio.db` 和 `data/dj-audio/` 通过一次迁移导入。迁移前停止写入或使用 SQLite 一致性备份，核对记录/音色/反馈数量，记录完成标志并回读。发现目标和旧路径各有数据时报告冲突，不静默选空库；旧资产仍能通过兼容路由访问。回退使用与迁移匹配的代码和数据快照，不用旧库覆盖迁移后的新记录。

## 5. 六片上下文与模型执行

### 5.1 组装合同

所有**需要模型**的触发都通过同一入口创建 `ContextSnapshot`，固定含六个片段；“暂停”“下一首”等直达命令遵循图中 router 规则，不为凑上下文而调用模型。

| 片段 | 输入 | 验收要求 |
| --- | --- | --- |
| ① 系统提示词 | `prompts/dj-persona.md` | 有版本；约束音乐为主、播报风格、歌曲资料归因与结构化结果 |
| ② 用户语料 | 四份 user 文件及明确反馈摘要 | 同一 profileRevision；缺失可见，不编造用户偏好 |
| ③ 环境注入 | weather / calendar / now | 带来源、时区、获取时间和可用性；日程包含所选日历当天已过、将来、全天事项 |
| ④ 已检索记忆 | messages / plays / plan / prefs | 按场景和近期相关性检索；去重、限制条数和长度，不把全部历史塞进提示词 |
| ⑤ 用户输入/工具结果 | 原文、规范化意图、搜索/歌词/候选结果 | 保留具体歌曲版本和输入身份；资料内容与应用指令分开 |
| ⑥ 执行轨迹 | scheduler / webhook / 尝试记录 | 可追溯为什么此时运行，重试不伪装成新请求 |

每片记录来源、版本/时间和截断信息；为当前指令与完整合同保留预算，旧聊天先摘要或裁剪，不能截掉日程后仍声称包含当天全部日程。空或失败片段也保留状态。用公开输入/输出验证改变片段能改变模型输入，不靠日志中出现“context”验收。

### 5.2 统一结果与执行权限

模型业务结果保持图片四个字段：

```typescript
type ProgramDecision = {
  say: string
  play: TrackReference[]
  reason: string
  segue: SegueProposal | null
}
```

这是待实施的合同草案：P2 在 `packages/contracts` 定义 `TrackReference` 和 `SegueProposal`，至少包含真实候选歌曲 ID/版本，以及串场目标、文案、claims、sources。任务标识、错误状态、usage 等放在应用结果信封，不能混作歌曲或播报。

- 网易云检索得到真实候选后才允许选歌；模型不决定完整音源权限、歌单内外归属、50/50 统计或永久屏蔽规则。
- `say` 是可展示的助手文字；只有节目播报或用户明确要求朗读的内容交给 TTS，不把所有聊天自动播出来。
- 模型返回可解析 JSON 仍需运行时业务校验。先校验，再准备音源和语音，最后发布终态；聊天文字增量不能提前改变队列。
- Claude 适配器支持结构化结果、流式事件、异常退出、超时、取消、配额失败及并发上限。以已登录订阅为目标，不自动回落到 API key 计费或另一供应商。
- 现有 Codex 可在迁移期作为显式回退选项；Claude 的真实选歌、资料撰稿和聊天验收通过前，不宣称 A05 完成。最终默认界面与诊断显示实际供应商。

图片 `--output json` 表达输出 JSON 的意图；实施使用官方有效参数 `--output-format json`，流式模式使用 CLI 支持的事件格式，不照抄无效参数。官方说明见 [非交互调用](https://code.claude.com/docs/en/headless) 与 [CLI 参数](https://code.claude.com/docs/en/cli-reference)。实际安装版本、Max 登录和订阅路径在 P2 核验；本次未核验账号，不能承诺已有额度。尤其不能为脚本便利启用要求 API key 的模式而偏离订阅目标。

## 6. 图示六条核心接口与实时状态

下面是目标协议，不表示已上线。登录、反馈、设置、曲库、音频和任务查询等辅助接口继续保留；“六条线”是核心交互合同，不是强制删除其余路由。

| 接口 | 目标语义 | 关键约束 |
| --- | --- | --- |
| `POST /api/chat` | 接收文字/明确命令，返回 requestId 与接收状态；通过 WS 交付增量和最终结果 | 带 clientMessageId、conversationId、sessionId（可空）、epoch、作用域；重试复用，不重复执行点歌或写偏好 |
| `GET /api/now` | 读取活动播放端最近上报的歌曲/播报、设备、进度、暂停和会话 | 含 observedAt、stale、playInstanceId；未观测时返回未知/未播放，不能把 plan 当作正在播放 |
| `GET /api/next` | 读取客户端待播队列的下一项投影；附可用准备结果状态 | 只读，不推进游标、不触发模型、不切歌；无客户端投影时 next 为空，prepared 单独标明 |
| `GET /api/taste` | 返回四份用户资料、版本及归一化偏好摘要 | 区分显式反馈、长期资料与会话调整；Profile 编辑通过另行定义的写接口保存 |
| `GET /api/plan/today` | 返回用户时区当天的持久节目计划、分段、版本和准备状态 | 无计划显式为空/待准备；GET 本身不生成节目；旧计划不冒充当天结果 |
| `WS /stream` | 聊天增量、工具/准备状态、计划变化、now-playing 通知；接收活动播放端观察 | 事件版本、序号、requestId/sessionId/epoch；按任务终态去重，连接建立不自动开播 |

实时事件至少覆盖 `chat.delta`、`chat.completed`、`chat.failed`、`preparation.changed`、`plan.updated`、`playback.observed`、`settings.updated`。这些名称是 P5 的规划草案，实施时统一写入 contracts。客户端收到完整准备结果只通过现有一个入口接纳；HTTP 与 WS 不能分别追加同一批。

聊天中的播放命令另有执行闭环：服务端路由出用户明确请求的 `playback.command`，携带 `commandId + sessionId + epoch + inputId`，只交给唯一活动浏览器控制器。控制器核验当前意图、去重并执行，回传 `playback.commandResult` 与实际观察；未连接、已过期、被浏览器阻止或未确认执行时，页面只能显示待执行/失败，不能回答“已暂停/已播放”。取消/重连不重放已执行命令。新开播命令关联输入请求，先按开播流程取得会话再执行；模型建议与定时事件不能伪装成用户控制命令。

WS 重连后先取得当前会话、任务、计划与播放观察快照，再按身份接纳事件；保存的聊天终态可以补读，不假定丢失的增量全部可重放。网页播放状态由网页上报，服务端只保存带时效的投影。多标签页只允许一个活动播放端发布有效观察并执行命令，其余是观察页；活动页租约到期不触发另一页自动出声。

迁移先增加 WS 并验证，再切换客户端的单一事件订阅，最后退役 SSE 或保留明确的兼容入口；不得让两个通道同时拥有业务状态。`GET /api/next` 与 `/api/now` 不改变 ADR-0003 的队列归属。

## 7. 节律调度、天气与日历

默认时区先沿用当前用户环境 `Asia/Shanghai`，之后由 `routines.md` 配置。所有“今天”和调度幂等键都按用户时区计算。

| 触发 | 必须执行的工作 | 不应产生的副作用 |
| --- | --- | --- |
| 每天 07:00 | 读取资料/环境/近期收听，生成当天分时段节目计划并准备首批内容 | 不下载全天所有歌曲，不自动出声，不预记播放 |
| 每天 09:00 | 刷新天气/日程，准备或更新早间播报；已在收听时交给当前节目选择自然衔接点 | 不打断当前歌曲，不重复播放已完成开场，不唤起已停止的会话 |
| 每小时 | 根据用户明确表达、作息与氛围规则检查后续安排；有变化才更新计划/发起准备 | 不凭空推断情绪，不强迫用户每小时回答，不无变化地重复生成语音 |
| 日历 hook | 日程新增/改期/取消后更新当天环境及受影响计划，合并短时间内重复事件 | 不重建整个播放队列，不把取消的日程继续播报 |
| 服务启动/睡眠恢复 | 检查到期且未完成的任务，合并错过的小时检查，补一次当前仍有意义的准备 | 不补跑一整夜的播报，不重放已经完成的任务 |

**规划解释：**图中的 09:00 是早间任务触发时间，未声明可以强制自动播放。用户当天在 09:00 前首次开播时，按现有领域定义准备开场天气/日程；09:00 不重复已完成的开场，必要时只更新变化。09:00 后首次开播使用新鲜的当日内容；晚上补执行时改写时态，不播放过时的“早安”。定时准备与实际播出分别记状态。

天气须配置城市；飞书须选择具体日历、读取完整当天范围并处理全天/跨日/取消事件。空日程与读取失败是不同状态。两者都有超时与缓存新鲜度；失败时显示缺失，仅准备可确认内容，恢复后补齐尚未播出的分段。已完成分段不因另一个来源恢复而重复。

Feishu 的读取与事件接入先复用本机 `lark-cli` 可用能力；P3 实施时核对目标账号的事件机制。若采用长连接收事件，统一归一为图中的日历 hook；需要 HTTP webhook 时由同一事件入口处理。轮询仅为降级补偿，不能单靠轮询宣称完成事件触发验收。

调度以 `(用户, 本地日期/小时, 触发类型, 事件版本)` 去重，保存任务状态和尝试次数；同一任务并发、重启或重复通知只形成一次有效产出。旧计划版本的结果不能覆盖新日历或新用户意图。服务关闭期间无法实际运行任务，恢复后补执行；PWA 的 Service Worker 不承担本机每日调度。

天气/日程播报携带 `planRevision + segmentId + environmentRevision`。日历变更不仅使在途准备过期，也使已合成、预取或入队但尚未播出的受影响分段失效；浏览器在播放前再次检查有效性，失效分段跳过，更新内容就绪后由浏览器按当前意图接纳。当前歌曲不中断，已播分段不因计划修订自动重复；变化确需说明时生成独立更新段，而非重播全部开场。

## 8. PWA、声音出口与音响

### 8.1 三视图与网页交付

- **Player**：当前歌曲/播报、播放控制、待播内容、聊天流、推荐理由、歌词、DJ 来源、天气/日程及今日计划。以音乐操作为主，细节按需展开。
- **Profile**：四份用户资料的查看/编辑、曲库同步状态、喜好反馈与撤销、长期偏好和会话调整的区分。
- **Settings**：音乐登录、Claude 状态、Fish 音色/DJ 频率、城市/时区、所选飞书日历、调度开关与时段、浏览器/Naim 输出设备、缓存状态。

目标构建入口是 `http://localhost:8080`；开发 HMR 可以保留独立端口，但 `/api`、`/tts`、`/stream` 必须代理到同一服务。新增 manifest、图标、安装体验和 Service Worker；应用壳离线可打开并显示缓存资料的时间，离线不能冒充可以调用模型或取得新歌曲。

缓存分别定义：应用静态资源可版本化缓存；账号、实时状态和写请求不缓存；TTS 按内容 hash 缓存；歌曲预取必须支持 URL 到期、Range/206 与账号变化。升级等待播放器安全时机，不能 Service Worker 更新就强制刷新正在播放的页面。敏感凭据不进入可离线页面数据。

**`prefetch 10s` 的规划解释：**距当前媒体自然结束约 10 秒时，预取当前确定的下一项；若当前时长未知，采用内容就绪后有界预取。图未指定是“提前十秒”还是“十秒媒体内容”，本计划采用前者。预取可用 fetch/缓存完成，不额外创建 `<audio>`；切歌/停止/来源变化使旧预取失效，命中缓存也不触发播放或记账。

### 8.2 UPnP / Naim

最终必须交付真实设备链路：发现 Naim → 选择设备 → 设置媒体 → 播放/暂停/停止/下一首 → 回读播放位置与状态。具体型号、支持的传输控制与格式在 P7 前置探针核对，不以库支持“UPnP”代替 Naim 实机验收。

**规划解释：**浏览器仍拥有节目队列和播放意图，Naim 是替换本机 `<audio>` 的声音出口。服务端只代理浏览器发出的带意图版本的设备命令，回传实际设备状态；不新增后台独立队列。网页关闭后不自动推进后续节目；“关闭网页也全天独立播放”不在图中明确要求，若以后需要，另行修订播放归属。

- 同时只启用一个声音出口。切换时先停止并确认旧出口，再启用新出口；无法确认时显示状态，不能让两个设备同时开始。
- 设备媒体 URL 必须可从局域网访问，不能把 `localhost` 发给音响；P7 增加显式启用的局域网媒体地址/监听配置，保留本机 PWA 入口。设备能实际拉到歌曲与 TTS 才算接入成功。
- 将 UPnP 观察状态映射成当前播放实例的实际开始、暂停、结束、故障；只有确认实际开始才记账。投送成功不能当作已经出声。
- 设备掉线、旧通知、播放端刷新和切回浏览器沿用当前意图代次；失败可提示切回，不在用户未选择时自动让电脑出声。

## 10. 最终验收场景

| 场景 | 必须观测到的结果 |
| --- | --- |
| 用户资料影响节目 | 修改口味/作息/氛围规则后，下次任务使用新版本；歌单文件失败不变成空曲库 |
| 六片组装可追溯 | 开播、聊天、定时和日历触发都能追到正确来源；模型收到的资料与当次版本一致 |
| 完整音乐能力 | 搜索区分版本、歌词可显示或明确缺失、推荐可播；试听音源不能当整曲；保留 50/50 与不喜欢规则 |
| 明确命令 | “暂停/下一首”直达唯一活动控制器并有实际回执；断线不报成功、不重复执行；“播放某首歌”经检索和版本选择；歧义时给可选项，不擅播另一个版本 |
| 自然语言调整 | “这会儿轻快一点，少说话”只作用本会话；明确“以后”才形成长期偏好变更 |
| 每日节律 | 07:00 形成计划，09:00 有早间内容；每小时无变化不打扰；错过触发可恢复，重启不重复播报 |
| 天气与日历 | 真实城市天气与所选日历当天全部事项；取消/改期会作废已合成或入队的未播旧分段；单源失败只影响对应分段 |
| 串播与朗读 | 真实歌曲→有出处的 DJ→歌曲；天气/日程朗读有正确时态；普通聊天不会全部自动朗读 |
| 暂停、停止与迟到结果 | 所有入口含聊天/定时/日历/WS/Naim 都遵守当前意图；暂停不出声，停止后的旧结果不接管 |
| 协议与恢复 | 六条核心合同可独立验证；WS 断线/乱序/重复/重启可恢复；GET 无播放或生成副作用 |
| PWA 与缓存 | 安装、离线打开、缓存版本升级、预取命中和失效；不创建第二个 audio、不缓存错误账号数据 |
| Naim 输出 | 真实设备拉到媒体、返回实际状态；切换/断网不双响，投送失败不伪记播放 |
| 持久化迁移 | 旧库资料完整、消息/计划跨重启保留、旧记录可读；默认路径与显式覆盖都有验证 |
| 计划到开播 | 07:00 无开放会话也可准备；开播重新确认音源和当前反馈；计划重试/过期/修订不创建假会话或虚假播放 |
| 两小时完整收听 | 正常 1x、无 seek 加速；包含自动跨批、DJ、开场、聊天调整、反馈与断线恢复；记录队列余量、补歌批次、实际进度及所有异常 |

两小时不能覆盖跨日调度：另保留至少跨一个本地日期、含真实 07:00 和 09:00 的调度观测。浏览器与 Naim 都需实际播放链路证据；一端通过不能代替另一端。Naim 设备暂不可用时 P7 标“未验收”，不能在总表中写已完成。

验证沿用 [隔离指南](../agents/verification.md)：先本地替身、再真实服务；分开报告。受影响的接口/状态机用公开行为测试，实际浏览器必须观察媒体进度；截图、health 和 HTTP 200 都不足以证明播放完成。后续测试使用独立数据库、登录态、缓存与 Chrome profile。文档规划阶段只做差异/链接检查，不跑全量应用测试。
