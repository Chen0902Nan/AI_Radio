# 探索选歌开发计划

## 已确认的产品行为

完整要求见 [开发规格](../../.scratch/discovery-selection/spec.md) 与 [访谈](../../.scratch/discovery-selection/interview.md)。默认 50% 歌单内、50% 探索，以最近 50 首真正开始播放的自动歌曲衡量；手动歌曲和 DJ 不计入。具体版本的不喜欢为硬排除，近期播放为可放宽排除。普通开播等混合首批，手动歌单结束后接回电台。

## 开发流程

参考 [Matt Pocock skills](https://github.com/mattpocock/skills) 的需求对齐、领域词汇、规格、纵向小步、TDD、类型检查与最终代码审查。遵循本项目本地 Markdown 任务管理，保护已有迁移改动，不提交或推送。

测试从公开接口观察结果，真实 SQLite 和业务服务参与；仅音乐平台、Codex 与浏览器媒体等外部边界使用可控替身。每次先观察失败，再完成最小实现，单文件回归通过后进入下一行为。测试范围已向用户提出：选歌接口、播放记录接口、浏览器交互，用户已确认。

## 实施顺序

1. 实际播放计数：自动歌曲携带服务端来源标识，首次 playing 提交实例 ID，重试与暂停恢复不重复，最近 50 条跨次持久化。
2. 混合候选与选歌：读取完整红心/收藏/自建歌单，拉取推荐及相似候选；按历史缺口选择可播结果，喜欢引导相似歌曲，不喜欢硬排除；近期不足可放宽并说明。
3. 首批与续播：开播先准备混合批次，手动歌单后接续；停止/切换后迟到结果失效，正常准备不当失败，提供反馈撤销。
4. 验证与审查：分页/不完整读取、生成失败、试听、无可播、迟到响应；类型检查、全量测试、浏览器与真实只读接口验证分别记录。

## 架构决定

延续 ADR-0003：浏览器拥有队列与播放意图，服务端只准备结果。新增持久播放来源与幂等键，旧播放记录默认为手动/未知，不伪造历史比例。平台歌曲 ID 作为具体版本身份。完整曲库记录按账号隔离；读取不完整且无完整记录时暂停新增探索，已确认歌曲可续播。候选抽样与最终配比不依赖模型遵守比例，模型只在真实候选中表达口味排序。

## 当前状态

实现、类型检查与本地全量 163 项测试已完成；真实资料/音源只读核验通过。浏览器三项回归通过，详细结果及验证边界见 [验收记录](../../.scratch/discovery-selection/verification.md)。
