# 技术债修复计划与验收

## 目标与原则

从可观察行为出发：队列与播放意图只有一个持有者；合法持久数据必须能被客户端读取；业务决策与副作用分开；质量约束阻止新的退步，而非机械清零历史例外。本次不改变探索比例、实际播放记账、暂停/停止语义及供应商协议。

## 执行顺序

1. 播放来源：通过浏览器交互复现慢歌单覆盖新选歌；把手动来源加载和模型选歌的异步生命周期收口到运行时，统一检查意图版本，组件不再直接修改队列条目。覆盖切换、停止和迟到失败。
2. 反馈契约：通过真实隔离 HTTP/SQLite 写入不带歌曲名的反馈，并用客户端合同读取；先失败再修复 null 兼容，保留非法类型拒绝。
3. 补歌流程：控制器只适配请求/响应；提取测试注入与输入解析。准备阶段明确结果类型，按候选、排序、发布职责拆分，保留每个 await 后的失效检查及原有降级行为。
4. 校验与播放决策：按目标身份、故事、引用、长度拆分校验，仍累计全部错误；任务校验按状态职责拆分；歌曲结束的资格判断与状态提交分开，保持重复通知不记两次。
5. 防回退：质量报告保留；新增机器可读例外基线及增量命令，新增超限或已登记指标恶化必须失败，函数移动不依赖行号。增加工具行为测试，默认检查不得自动更新基线。
6. 类型收紧：在上述修改范围内以明确结果联合类型替代宽泛结果对象，错误提示从 unknown 安全读取。其余有依据的局部边界不为形式统一而重写。

## 验收边界

沿用已确认的公开入口：服务端 HTTP、播放记录、浏览器用户操作；合同校验保留现有公开函数测试。新增质量命令通过 CLI 验证退出状态。按单项失败→修复→通过推进，结构调整复用现有行为回归。

完成后执行 npm run typecheck、npm test、npm run test:browser、增量质量检查及 git diff --check。浏览器使用本地接口与媒体替身，不调用真实供应商，不改真实 data/。不提交、不推送；保护当前未提交整改。

### 行为与结构

- 新增 `SourceSelection`，歌单、Codex 选歌、手动点播共用运行时意图版本；成功与失败响应均检查版本，组件卸载后拒绝接纳。初始曲库加载也不能覆盖后续来源操作。删除无调用方的旧 `loadLibraryInto` 入口。
- 队列读取返回只读条目；手动点播通过 `PlaybackController.playManual` 修改自动标识，组件不再直接写队列。手动点播同步 DJ 版本，实际播放记录不带 selectionId。
- 反馈合同接受合法 null/缺省歌曲名，非法对象仍拒绝；数据库/API 行为不变。
- HTTP 控制器提取输入适配、状态映射及测试注入；补歌结果改为成功/失败联合类型，删除“null 假装 Promise/string”的两处双重断言。失效检查仍保留在每个异步阶段完成后。
- 文案和任务校验按职责拆分，保留累计错误及错误路径；播放结束先判断身份和资格，再更新状态。
- 新增 `check:quality:delta`，纳入 `npm test`；机器基线人工下调到 51 个保留例外，检查本身不写基线。
