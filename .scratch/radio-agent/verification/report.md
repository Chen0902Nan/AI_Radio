# 第一阶段验证报告：音乐资料 → 完整歌曲 → 本地网页播放

日期：2026-09-14
范围：只验证「读取本人网易云音乐资料」「获取有权播放的完整歌曲」「本地网页播放」，含下一首与单曲失败换歌。不含 DJ、TTS、天气、飞书日历、聊天、每日调度。
结论：**链路打通，14 项浏览器检查全部通过**。官方网易云 CLI 路线因缺少开放平台凭据受阻，本轮改用参考方案里的音乐 API 方向。完整产品仍未实施、未验收。

## 1. 采用的接入方案及版本

| 组件 | 版本 / 位置 | 用途 |
| --- | --- | --- |
| Node.js | v24.16.0 | 运行时 |
| `@neteasecloudmusicapienhanced/api` | 4.40.1（项目内 `node_modules`） | 网易云数据读取与音源查询 |
| `@music163/ncm-cli`（官方） | 0.1.7（项目内安装，未使用） | 仅用于核实接入前提 |
| `puppeteer-core` | 25.11.0（devDependency） | 驱动系统 Chrome 做真实浏览器验证 |
| Google Chrome | 152.0.7977.83（headless=new，系统安装版） | 真实播放验证 |
| 系统 | macOS 26.6.2 (arm64) | — |

**为什么不是官方 CLI。** 官方 `@music163/ncm-cli@0.1.7` 已在本机安装并核查：未配置凭据时任何命令（含 `--help`）都直接退出；用临时 HOME 写入假凭据后，`--help` 与 `commands` 只列出静态命令（play/pause/state/login/tui/configure 等），**`search`、`playlist`、`user favorite` 等资料命令来自远端动态 manifest，必须有有效的开放平台 appId + privateKey 才会注册**。凭据来自网易云音乐开放平台个人入驻，本机没有。另外该 CLI 的播放由 mpv 承担，不能用来验证网页播放；也没有找到稳定公开、无播放副作用的取音源命令。

**因此采用 API 方向，边界明确：**
- 只用标准只读接口：`/api/song/like/get`、`/api/v3/song/detail`、`/api/user/playlist`、`/api/v6/playlist/detail`、`/api/song/enhance/player/url/v1`、登录相关接口。
- **不传 `unblock` / `match` 参数，不启用任何额外音源**，只返回当前账号本身有权播放的内容。
- 登录用手机扫码（`ncm-cli` 之外的独立流程），cookie 只写本机 `data/session.json`（权限 0600），前端永远拿不到 cookie，也拿不到带鉴权参数的 CDN 直链（音频经本服务转发）。
- 额外副作用说明：首次运行会向网易注册一个**匿名设备 token** 用于辅助查询，这不修改用户的红心、歌单或任何音乐数据。账号内没有任何写操作。

本轮验证使用的账号：`Pluto_Magic`，uid `1734543760`（VIP）。

### 分页检查（有实测发现）

- 红心歌曲 `/api/song/like/get` **一次返回全部 id，没有服务端分页**；歌曲详情按 300 条分块请求（456 条 → 2 块）。
- 歌单列表 `/api/user/playlist` 的实际行为和直觉不同，实测确认：
  - **`limit` 参数被服务端忽略**（传 `limit=2` 仍返回全部 6 个）；
  - **`offset` 正常生效**（`offset=6` 起返回 0 条）；
  - **`more` 恒为 `false`**，不能用来判断是否还有下一页。
  - 首版实现依赖 `more` 判断，只是"碰巧正确"。已改成按实际返回条数推进 `offset` + 去重，并用 `pageSize=2/4/50` 三种尺寸复测，结果集完全一致（`pageSize=2/4` 时真的走了 2 页）。
- 错误处理：不存在的歌曲 id（`999999999999`）不抛异常，被正确归类为"不可播放"；接口失败会带 code 抛出，不会当成空歌单。

### 3.2 真实浏览器播放记录

浏览器：系统 Chrome 152，headless=new，通过 puppeteer-core 驱动；播放策略设为 `document-user-activation-required`，即**必须先有点击才允许出声**。

| 观察项 | 记录 |
| --- | --- |
| 页面加载后是否出声 | 否，`paused=true` 且 `<audio>` 无 src |
| 点击播放 | `爱情转移`（id 65536，陈奕迅，曲目时长 260.0s） |
| 播放器报告的时长 | 259.99s，与曲目真实时长一致（证明是完整歌曲，不是试听片段） |
| 自然播放结束 | `ended` 事件 `currentTime=259.986667`、`duration=259.986667` |
| 墙钟耗时 | 260.0s（与真实时长差 < 0.1s，没有加速、没有跳段） |
| 进度采样 | 174 个采样点，进度单调递增，最大单点跨度未超过阈值（未拖动进度） |
| 点击下一首 | 65536 → 65538 `好久不见`，确认为另一首真实可播歌曲 |
| 结束后自动续播 | `ended` 后自动切到 65538，符合预期 |

网络轨迹：音频请求全部走本服务 `/api/audio/<id>`，返回 200/206（206 为 Range 分段），无跨域或鉴权头问题。

### 3.3 故障注入与恢复

| 场景 | 做法 | 结果 |
| --- | --- | --- |
| 单曲音源失败 | `POST /api/_test/fail-next`（仅 `RADIO_TEST_HOOKS=1` 时开放）注入 1 次解析失败 | 该曲（id 167937）被标记失败并暂停旧音频，**1.2s 后自动换到 id 25638273 `梦想天空分外蓝` 并恢复播放**；实测退避 1205ms |
| 连续失败 | 注入 20 次 | 连续 3 首失败后**停止自动换歌**并显示「连续 3 首无法播放，已停止自动换歌」；观察 10.5s 内解析尝试只增加 3 次，**没有快速重试** |
| 真实无权限曲目（非注入） | 直接点击 `残酷月光`（id 108557） | 明确提示「账号当前无播放权限」，自动换到 id 26584453 `梦伴` 并继续播放 |

## 4. 交付物与复现方式

```
server/netease.js      接入层：扫码登录、资料读取、音源解析与分类、地址缓存
server/index.js        HTTP 服务：静态页 + JSON API + /api/audio/:id 音频转发（含 Range）
public/                最小播放器：歌曲信息、播放/暂停、下一首、状态提示、红心与歌单列表
scripts/read-library.mjs     资料读取与分页/去重检查（输出不含凭据的报告）
scripts/verify-playback.mjs  真实浏览器播放与故障恢复验证
data/                  登录会话（已 gitignore，权限 0600）
```

```bash
npm install
npm start                       # 正常启动，http://127.0.0.1:8787
node scripts/read-library.mjs   # 读取真实资料（需已登录）
# 验证用（带故障注入）：
npm run start:test              # RADIO_TEST_HOOKS=1 node server/index.js
npm run verify:playback         # 真实浏览器验证（约 5~6 分钟，含一首完整歌曲）
```

登录：浏览器打开 `http://127.0.0.1:8787/login`，用手机网易云音乐 App 扫码。二维码只在本机使用。

## 5. 未验证 / 未完成

- **试听片段（trial）分支**：本账号是 VIP，未遇到真实样本。
- **播放地址失效后的刷新重试**：代码已实现（先刷新一次地址，仍失败再换歌），但没有可控办法制造真实的 CDN 地址过期，**未实际验证**。
- **超过 6 个歌单、多个分页的真实多页场景**：账号只有 6 个歌单，`limit` 又被服务端忽略，多页收敛主要靠合成数据之外的推演。
- **官方 `ncm-cli` 的音源能力**：缺开放平台凭据，完全未验证。
- 音频输出是 headless Chrome 的真实解码播放，没有用系统扬声器做人工听感确认。
- 未做 2 小时连续收听验收，未实施 DJ/TTS/天气/日历/聊天/调度。

## 6. 下一步建议

1. 若希望回到官方 CLI 路线，需要先完成网易云音乐开放平台个人入驻（appId + privateKey），这属于你本人要做的账号操作；拿到后再复核动态命令的真实输出与音源权限。
2. 播放地址刷新路径建议用一个本地可控代理（主动让某个地址失效）补一次真实验证。
3. 进入后续开发前，先把"音源解析 + 待播队列 + 失败策略"从本轮的验证代码里收敛成编排层可复用的接口，避免第二套并行实现。
