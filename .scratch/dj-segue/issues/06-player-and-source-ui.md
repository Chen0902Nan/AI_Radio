# 06 · 单音频串播、控制及文案来源界面

Status: ready-for-agent
Type: task
Depends on: 04
Execution: done
确认依据：Q9 已整体确认；按前置任务顺序执行。

## 目标

通过现有一个 `<audio>` 完成歌曲→DJ→歌曲，保留用户对暂停、跳过、停止的控制，并能看到播报内容和出处。输入：[播放契约](../contract.md)、04 控制器；可先使用 01 的接口替身。

## 范围与输出

- 负责 `public/app.js`、`public/index.html`、`public/style.css`。把歌曲解析与 DJ 音频加载分派到同一执行入口。
- 改掉纯歌曲假设：`loadedSrcId`、补歌 pending/exclusion、列表身份、错误恢复、当前媒体归属、喜欢按钮和 `plays` 记录。
- 接入 04 的准备/取消/播放决定；歌曲 ended 与 DJ playing 只报告正确条目的有效事件，不另写一套频率算法。
- DJ 显示标题、下一首歌曲、当前文案及可点击来源；民间说法的归因由实际稿件承担，网页保留来源供查看。
- 维持当前布局加入 DJ 开关、间隔选择和服务/音色状态；停止收听时提供主动试听入口，用同一个 audio，试听不记歌曲历史或改变计数。
- 暂停从原位置恢复；下一首直接进歌曲；关闭 DJ 按契约结束播报或取消准备，已暂停时只能进入目标歌曲待播状态，不能自动出声。改设置不打断正在播放的歌曲。

## 验收

- 歌曲自然结束→ready DJ→目标歌曲连续执行，只有一个音频出口，无同时出声。
- DJ 暂停恢复正确；DJ/歌曲中的下一首都直接进下一首歌曲；停止、切来源、连续点击后旧回调不抢播、不暂停新媒体。
- 文案/TTS 迟到、加载失败、目标不可播直接继续歌曲，语音错误不累计为连续歌曲失败。
- 待播补歌数只数歌曲；重复入队歌曲仍按条目标当前；DJ 不写歌曲播放记录，期间喜欢/不喜欢/撤销不可操作。
- 来源标题/链接可查看，文案与正在播放的音频版本一致；无配置/冷却/略过原因以简短状态显示。
- 与现有补歌、暂停加载、音源刷新、会话/反馈的浏览器回归兼容。

## 边界

不新增播放器、UI 框架或整站改版；不把真实密钥放前端。与 05 可按固定契约并行，不以真实 TTS 凭据阻塞界面和故障测试。
