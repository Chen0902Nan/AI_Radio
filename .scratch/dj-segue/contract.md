# DJ 串场开发契约

状态：2026-09-16 经 Q9 整体确认的开发基线；代码尚未实现以下接口。
产品行为以 [spec.md](spec.md) 的 Q1–Q8 为准；常规参数已随 Q9 确认。

## 1. 身份与职责

继续沿用 ADR-0003：网页拥有节目队列和播放决定，服务端只准备内容。所有声音经过现有单个 `<audio>`。

| 名称 | 含义与约束 |
| --- | --- |
| `sessionId` | 当前收听会话；停止后旧会话的结果一律失效 |
| `epoch` | 编排版本；切来源、应用新计划或重置节目时更新，不能直接用暂停也会变化的 `playToken` 代替 |
| `itemId` | 一次入队的节目条目身份；同一首歌重复入队也不同 |
| `trackId` | 音乐平台歌曲 ID；旧歌曲对象的数字 `id` 可在适配边界映射，不用于识别一次串场机会 |
| `transitionId` | 本次“当前歌曲结束 → 目标歌曲开始”的串场机会；包含当前/目标条目关联，机会关闭后不重新打开 |
| `segueId` | 一次准备任务及其播报成品身份；可用于查询、取消及媒体归属 |
| `playInstanceId` | 一次实际播放尝试；暂停恢复复用，重新开始同一条目则新建，供 ended/首次 playing 去重；独立于数据库异步取得的歌曲 playId |
| `playToken` | 播放执行的代次；控制加载/播放回调能否生效，与准备任务版本分开 |

`track` 与 `segue` 是两种节目内容。歌曲反馈、歌曲播放记录、补歌去重和待播歌曲数量只看 `track`；播报有独立的媒体身份、失败与生命周期。来源只由生成结果传递，网页不从文案猜测链接。

## 2. 频率与准备时机

- 默认 `djIntervalTracks=4`，可选 3/4/5；`djEnabled=true`，无可用语音配置时显示 DJ 不可用并继续音乐。
- 只在当前歌曲播放实例的有效 `ended` 累计一次。手动下一首、直接选曲、解析/播放失败、DJ 的 `ended` 均不累计。
- 进入歌曲时，已自然完成的歌曲数达到当前 `djIntervalTracks - 1`，且已知紧邻下一首，就提前准备目标歌曲的串场；依据的是自然完成数，不是歌曲开始次数。计数已到期但上次未播时，进入后续歌曲便再次准备其下一首。短歌曲不保证留够生成时间，到点遵循略过规则。
- 自然结束时作一次决定：达到间隔、语音完整就绪、目标仍是紧邻下一首且已确认有完整音源 → DJ；否则关闭机会并继续音乐。
- 判断关闭后，迟到结果不得重开机会、改变当前歌曲或补插播报。下一次准备使用新机会及新目标。
- DJ 首次有效 `playing` 才将计数清零；同一条目暂停恢复的后续 `playing` 不再次清零。DJ 未出声就失败或被取消不清零；已出声后失败或被跳过仍算使用过本轮机会。
- 缺少下一首时先按现有补歌流程取得歌曲，不凭空生成无目标串场；队尾等待的补歌结果到达后优先恢复歌曲。
- 暂停可保留在途结果，但不启动新准备、不让结果出声；停止清空机会、计数和任务绑定。刷新后不自动出声、不恢复旧播报。

## 3. 资料与文案

输入仅包含已确认的目标歌曲标识/基础信息、必要的收听氛围、文案要求和当前机会身份。一次 DJ 请求内完成搜索与写稿，避免为一句故事发起多个无界模型调用。

建议输出形状（字段的验证规则由任务 01 固定）：

```text
scriptText
storyStatus: sourced | basic_only
claims[]: id, text, kind, sourceIds[], spokenAttribution
sources[]: id, url, title, publisherOrAuthor, evidence, retrievedAt
```

- `kind` 为 `documented`（所读取资料支持的陈述）或 `unverified_account`（有出处的传闻/民间说法）。`documented` 也不等于对客观真实性的绝对保证。
- 论坛、个人文章、乐迷分享可以作为来源，不设“只允许官方域名”的白名单。关键是实际访问到的来源内容与目标歌曲/歌手对应。
- 未证实说法必须在 `scriptText` 中自然说明来源及其说法性质，例如“有乐迷在某论坛分享过一种理解……”。不能只在 `claims` 或网页中标记。
- 不同来源存在不同版本时，可归因讲某个版本或说明存在不同说法，不拼成一个已确定的故事；15–30 秒容不下清楚归因时，少讲内容。
- 网页显示文案与完整可点击出处，语音不朗读 URL。来源原文只保存支持陈述所需的短摘录或摘要，不缓存整篇文章作为节目资料。
- 搜索失败、只查到不足以支撑陈述的摘要、来源无法访问或未找到资料时，允许返回 `basic_only`，仅介绍已知歌名/歌手及氛围。整个 Codex 请求失败则跳过本次 DJ。
- 结构检查覆盖非空稿、长度范围、目标歌曲、来源引用存在、未证实说法的归因文字；它不能证明来源支持内容。须保留必要搜索活动摘要并用真实案例核对，不能把模型声称“查到了”当证明。
- 搜到的文本是资料，不能改变本应用指令、运行外部命令或扩大输入信息范围。

## 4. Fish 合成与本地音频

- 服务端配置密钥；候选 `reference_id` 可以由用户主动试听，正式节目只使用已经选定的音色。未配置密钥/有效声音 ID 时返回不可用状态，不发起合成；前端不接收密钥。
- `model` 请求头显式固定 `s2.1-pro-free`，配置缺失/未知值直接拒绝，不让供应商默认回落到付费模型。实施真实验证前回读当日官方免费政策；没有明确免费准入则停止该接入测试。
- 首版收齐 MP3 再提供同源音频地址；任务成功必须是有效音频，不是 HTTP 200 的错误文本或未写完文件。
- 缓存键包含完整文案、模型、音色及影响声音的参数；音色变化不能命中旧声音缓存。文案及来源元数据关联到同一个版本。
- 缓存默认 TTL 24 小时、活动目录上限 100 MiB；使用中的音频受保护，无法腾出空间时本次语音降级，不无限扩容。淘汰和测试临时文件清理遵守项目“移入废纸篓、不自动清空”的规则。
- 文案按 15–30 秒准备，记录实际音频时长；不得硬截断句子。超过 30 秒的音频不进入正式节目，收窄文案后只能为后续有效机会再准备，禁止在同一次机会无限重生成。少于 15 秒的有效基础介绍允许降级使用，并明确记录时长偏差。
- DJ 与歌曲使用同一音量控制，首版没有叠加背景音乐、淡入淡出混音或第二个播放器。

## 5. 准备流水线与接口

拟新增路由（由任务 05 统一接入）：

| 接口 | 职责 |
| --- | --- |
| `POST /api/dj/prepare` | 提交 `sessionId/epoch/transitionId/fromItemId/targetItemId/targetTrackId` 和有限上下文，返回准备任务或复用已有任务 |
| `GET /api/dj/jobs/:segueId` | 返回 `preparing/ready/unavailable/stale` 及阶段、原因；ready 包含成品文案、来源、音频地址与时长 |
| `POST /api/dj/jobs/:segueId/cancel` | 幂等地作废任务的排程资格；不会停止歌曲或其他机会 |
| `GET /api/dj/audio/:assetId` | 提供已完成的同源 MP3；不接受任意外部 URL 或文件路径 |
| `POST /api/dj/preview` | 停止收听时，为用户选中的候选音色合成固定短试听稿；遵守同样的免费/超时约束，返回音频地址，不创建节目机会或歌曲历史 |

状态可以在进程内保存；服务重启后旧任务按失效处理，不扩展为持久化服务端播放队列。任务状态保留至完成后 5 分钟，缓存文件独立按 TTL/容量管理。

- 同一个 `(sessionId, epoch, transitionId)` 的重复提交复用任务；不同 payload 不能悄悄复用同一键。
- 同一会话最多一条有效 DJ 准备流水线。关闭旧机会时尽力取消对应 Codex/TTS，无法撤回的请求只允许释放资源或形成独立缓存，不能改动新机会。
- Codex 默认上限 90 秒、TTS 60 秒、整条准备最多 150 秒；各阶段受同一个总截止时间约束，机会失效则更早取消。这些是控制上限，不是体验延迟保证。
- 当前机会失败不原地自动重试；下一机会可再次尝试。连续服务失败采用 60 秒到 15 分钟的有界冷却；配置/认证错误在配置更新前不重复请求。冷却期间继续音乐。
- 不阻塞已有补歌接口。音乐候选、DJ 文案和 TTS 的失败状态分开，不让一次语音故障计入“连续三首歌曲失败”。
- 目标歌曲的完整音源在准备及使用前校验；播放边界不等新网络请求完成 DJ 的 ready 条件。目标已经确定不可播时撤销 DJ，沿用现有歌曲失败恢复。
- DJ 出声后才发现目标音源失效时，停止过时介绍并进入歌曲失败恢复；音源在校验后仍可能失效，不能宣称可撤回已播出的介绍。

## 6. 播放与界面

- 任务 04 提供无 DOM 的串场控制器：接收歌曲开始/自然结束、队列改变、暂停/恢复/停止、请求结果；返回准备/取消/播放 DJ/继续歌曲等决定。任务 06 执行决定并维护实际 `<audio>`。
- `playing/ended/error`、异步 `play()`、歌曲地址刷新和语音加载均校验当前媒体身份及代次，旧回调不得暂停或跳过新媒体。
- 用户点下一首总是进入下一首歌曲，不先插入已准备的 DJ；若当时正在说话，下一首是该播报原本介绍的目标歌曲。
- DJ 暂停恢复保持当前位置；暂停时请求完成只更新准备状态；停止、换来源、重新排队后旧结果失效。
- DJ 期间显示“DJ 串场”、目标歌曲、文案和来源；歌曲喜欢/不喜欢/撤销按钮禁用，播报不写入歌曲 `plays`。
- 关闭 DJ 时取消未播任务；若 DJ 正在出声则结束它并进入后续歌曲，若 DJ 已暂停则只切到目标歌曲待播状态，保持暂停直到用户点击继续。改频率/音色作废未播成品，当前歌曲或已出声 DJ 播完再用新设置。
- `djEnabled/djIntervalTracks/djVoiceReferenceId` 用现有本地设置存储，`djVoiceReferenceId` 只在用户选定声音后保存，作为正式节目唯一音色来源；模型固定在服务端，密钥来自服务启动环境。候选 ID 经 preview 试听，不能自动覆盖已选音色。
- 试听不进入节目队列、不改变频率或歌曲历史；复用同一个音频出口，仅在停止收听时允许试听，避免打断节目。具体音色由用户接通后试听选定。

## 7. 验证边界

离线/替身测试证明状态和失败行为；真实 Codex 证明搜索与结构化稿；真实 Fish 证明免费准入和语音；真实浏览器才证明歌曲 → DJ → 歌曲。

真实演示至少保留一次前曲自然结束、串场完整结束、后曲实际出声及进度增长，且没有拖动快进来冒充自然完整播放。还应分别覆盖资料型故事和有出处的民间说法，核对语音中的归因及网页出处。

原有歌曲播放、补歌、会话/反馈的回归按改动范围运行；本功能通过不等于完成原规格两小时、开场天气/日历及聊天等整体产品验收。
