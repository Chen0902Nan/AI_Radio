# DJ 串场：开发规格

状态：Q1–Q9 已确认，开发编排已定稿；代码实施尚未开始。
日期：2026-09-16
现场基线：`f5ff091`；开始调查时工作区干净。

## 目标与范围

完成普通歌曲之间的「检索有明确出处的歌曲资料 → Codex 生成 DJ 文案 → Fish Audio 合成语音 → 播放器依次播放歌曲、串场、歌曲」开发编排。本文记录事实、已确认行为和实现方案；独立任务见 [开发任务与依赖](plan.md)，接口及状态规则见 [开发契约](contract.md)。

本轮按用户指定的歌曲串场范围梳理；天气、飞书日历及当天开场不是这条链路的前置依赖，仍由原完整规格另行跟踪。开场播报不能套用普通串场的时长限制。

## 继承的要求

来源：[原规格](../radio-agent/spec.md)、[逐项访谈](../radio-agent/interview-record.md)、[领域词汇](../../CONTEXT.md)。原规格整体状态行与后续实现记录有出入，不能据此判断目前仍未开始开发；本轮按具体已确认条目及当前源码分别取证。

- 音乐为主；普通串场默认每 3–5 首一次，每次 15–30 秒，温和简短，初始设置可调整（原 Q7）。
- 普通话为主，使用 Fish Audio 现成的温暖、自然音色，接通后试听确定具体音色（原 Q19）。
- 文案通过本机 Codex CLI 复用现有订阅；不改成默认使用按量付费模型 API（原 Q14、ADR-0001）。
- Codex 或语音服务不可用时跳过 DJ，继续已有可播放歌曲（原 Q14、Q15）。本轮 Q4 进一步确认限定零新增语音费用，免费不可用不切付费服务。
- 准备不等于开播；只有用户开始收听才出声（原 Q5）。
- 下一首不代表不喜欢；暂停/停止及过期异步结果不能导致自行出声。
- 沿用 [ADR-0003](../../docs/adr/0003-orchestration-queue-ownership.md)：网页持有节目队列和播放意图，服务端负责准备内容，不新建第二个音频播放调度器。

## 当前代码事实

| 环节 | 现状 | 主要入口 |
| --- | --- | --- |
| Codex | 仅返回选歌 `picks[{id, reason}]`；没有播报稿生成 | `server/codex.js`：`PICK_SCHEMA`、`pickTracks` |
| 后台准备 | 有批次去重、会话失效、Codex 冷却与曲库降级；当前输出歌曲 | `server/orchestrator.js`；`server/index.js` 的 `/api/queue/refill` |
| 客户端补歌 | 有待播阈值、异步结果作废与退避；待播数仍直接数队列条目 | `public/orchestrator.js`；`public/app.js` 的 `pendingCount` |
| 播放 | 单个 `<audio>`；非 `track` 条目直接跳过 | `public/app.js`：`playIndex` |
| 暂停与恢复 | 已用播放意图代次保护；实际媒体身份只认歌曲音频路径 | `public/app.js`：`pausePlayback`、`loadedSrcId` |
| 记录与反馈 | 播放记录、喜欢/不喜欢均按歌曲处理 | `public/app.js`；`server/index.js` 的 `/api/plays/*`、`/api/feedback` |
| TTS | 没有供应商适配、合成路由、播报音频缓存或播放路径 | `server/` 与 `public/` 全量相关文件调查 |

当前进程的 `FISH_API_KEY`、`FISH_AUDIO_API_KEY` 都未设置。仅检查是否存在，没有读取密钥值；不能由此判断其他运行环境或用户账户是否已有凭据、额度。

本轮没有启动服务、调用 Codex/TTS 或重跑浏览器验收。以往音乐链路验证不能代替 DJ 链路验收。

## Fish 官方资料核验

2026-09-16 只读回读官方文档，未调用合成接口。

- 当前 [API 定价](https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits) 明列 `s2.1-pro-free` 为免费开发模型；普通 `s2.1-pro` 为每百万 UTF-8 字节 15 美元。公开定价不证明用户账户已具备可用密钥或准入资格。
- [TTS 接口](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech) 使用 `POST /v1/tts`、Bearer 认证；`model` 是请求头，`reference_id` 用于选择声音，二者不可混淆。支持 MP3 等音频格式。
- 接口文档明确：省略或传入无法识别的 `model` 会回退到 `s2.1-pro`。因此免费路径必须显式固定并校验 `s2.1-pro-free`；配置错误与失败重试不能变成付费回落。
- 真实账户准入、音色访问、生成时长和中文听感尚未验证。免费模型的可用性与延迟不能作为产品保证。

## Codex 搜索能力核验

2026-09-16 只读核验项目指定 CLI（0.153.4）及官方文档，没有运行模型请求。

- 本机 `codex exec -c 'web_search="live"' --ignore-user-config --sandbox read-only --output-schema <schema> --json -o <output>` 的 help 参数解析可共存。`codex exec --search` 则不接受该参数位置，不应直接照抄顶层开关到 exec 后面。
- [官方搜索说明](https://learn.chatgpt.com/docs/web-search)将搜索定义为托管工具，无需为它放开本地读写权限；[配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)支持单次显式覆盖。
- [非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)说明 JSONL 事件与最终结构化输出可以分别获取。当前项目仅解析选歌最终结果，没有 DJ 搜索证据处理。
- 待实现的 DJ 契约应保留文案中采用的陈述及其性质、对应来源 URL/标题/证据摘要和检索时间；不能用选歌理由、孤立 URL 或模型自称已搜索作为证据。Q5 允许有出处的传闻，须区分“来源确实这样说”与“内容已证实”。
- 尚未验证实际账户搜索能力、该版本搜索事件的完整字段及“搜索 → 阅读来源 → 结构化文案”的真实输出。结构校验不等于来源足以支持事实；必须做真实样例核对。

## Q9 整体确认方案

2026-09-16，用户原文：“确认，按此编排”。以下具体默认值、开发契约及 8 项独立任务已作为开发基线确认。

- **初始频率**：每自然播完 4 首歌安排一次，设置可调整为 3、4、5 首或关闭 DJ。歌曲播放失败、主动跳过、直接选曲不累计；初次开播从 0 计数，先播放音乐。
- **一次播报**：介绍紧邻下一首，主要挑一个故事，15–30 秒为目标；有来源的传闻可用“某位乐迷在某论坛分享过一种说法……”等自然表达，不能只在网页角落标注来源。网页显示完整文案及可点击出处，不朗读 URL。
- **查无资料**：搜索失败或没有可核对出处时，退回已知歌名/歌手及氛围衔接；若整个 Codex 调用失败则跳过 DJ。不会为了凑故事编造出处。
- **后台准备**：歌曲播放期间准备后续串场。到自然结束的间隙还没就绪，就继续下一首并放弃本次机会；旧结果不能插入已开始的歌曲。DJ 首次实际出声才重置计数，暂停恢复不会再次重置。
- **控制与展示**：暂停保留当前播报位置，继续从原位置播放；下一首直接进歌曲；停止清空本次串场机会。播报期间歌曲喜欢/不喜欢按钮禁用，界面显示“DJ 串场”和即将播放的歌曲。
- **设置变化**：关闭 DJ 即结束当前播报并进入后续歌曲；若当时已暂停，保持暂停等待用户继续，未出声的旧任务作废。改频率/音色只影响之后准备的串场，不打断当前歌曲或正在播的串场。设置保存在本机；聊天式临时调整仍属后续功能。
- **音量与缓存**：使用现有统一音量，首版不叠背景音乐；语音缓存有过期及容量限制，来源随对应文案保留。具体参数见开发契约。
- **免费接入**：固定已核验的 Fish 免费模型，不自动切换付费。凭据接入与音色试听作为独立任务，缺少凭据不阻塞其他开发，但真实合成和浏览器验收必须明确标为未完成。
- **交付范围**：本次交付开发规格、契约、独立任务和验收方案。整体确认指这些成为开发基线；不会将“开发编排完成”写成“功能已经实现”。

## 开发拆分必须覆盖的内容

以下检查项已落实到独立开发工单；各工单范围和验收以链接文档为准，尚无实现完成记录。

1. 契约：区分歌曲和串场、队列条目身份与歌曲身份；说明串场绑定的歌曲及过期条件。
2. 资料与文案：核验 Codex 搜索能力；检索歌曲故事，留存来源与陈述对应关系，再生成结构化播报稿。允许有出处的民间说法，但必须在实际播出文字中归因；检查空稿、超长稿、错误歌名、无出处或把传闻写成定论；生成慢不能拖住音乐。
3. 语音：Fish 服务端适配、明确模型和音色、请求超时与有界恢复、本地音频提供、缓存容量/过期清理。
4. 准备协调：文案再合成音频，避免同一段重复生成；暂停后只准备不出声，停止或换来源后不应用旧结果。
5. 播放：单个 `<audio>` 串行接力；调整类型分派、实际媒体身份识别、补歌数量、进度显示、反馈及播放记录。
6. 验证：离线控制与故障场景、真实 Codex 和 Fish 合成、真实浏览器完成歌曲 → DJ → 歌曲；分别报告各层证据。

## 验收底线与待细化场景

- 正常路径：准备不打断当前歌曲；满足播报规则时播放完整串场，播完后进入正确歌曲。
- 慢与失败：文案超时、TTS 超时/限流、音频缺失或解码失败均不能卡住可播放的歌曲；恢复后不重复插入旧串场。
- 控制：生成期间暂停、播报中暂停/恢复、跳过、停止后重开、切来源、连续点击均遵守最新播放意图。
- 内容一致性：为某首歌准备的介绍不能跟在另一首歌前播放；目标曲不可播时应有明确处理。
- 类型隔离：DJ 不算歌曲、不影响歌曲喜好、不能假装是可补充的音乐数量，也不能误用歌曲音源刷新路径。
- 真实证据：至少完成一次真实歌曲自然结束 → 真实合成播报结束 → 下一首真实歌曲继续播放；试听评价与音色选择单独记录。
- 与完整产品区分：本功能验收不等于完成开场/天气/日历/聊天，也不代表通过原产品的两小时完整验收。
