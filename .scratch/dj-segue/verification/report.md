## 2. 已覆盖的故障与竞态场景（离线）

- 文案超时/额度/认证/无效输出 → 任务 unavailable + 有界冷却；配置/认证错误阻塞至配置更新。
- TTS 超时/取消/限流/错误正文/中断/超大 → 不产出 ready 成品，音乐不受影响。
- 同键重复提交复用任务；同键不同 payload 明确拒绝；每会话单流水线自动作废旧机会。
- 就绪早于/晚于自然结束两种顺序：迟到结果按 requestId+transitionId 双重丢弃，不重插。
- DJ 未出声失败不清计数（下一机会可再准备）；已出声被跳过算使用（完整重新累计）。
- 停止/换来源/epoch 变更清空机会、计数与任务绑定；旧任务 finally 不触碰新任务。
- 缓存并发同键不产生半成品；损坏 meta 可被清理；淘汰只进废纸篓、绝不误删其他文件。

## 3.7 `playing` 媒体归属修复（2026-09-17，TDD）

原则：浏览器的出声事件只能确认实际装载的播放实例，不能替界面已选中但仍在解析的新歌曲记播放历史。
`public/app.js` 的 `playing` 处理现与 `ended/error` 共用 `mediaOwnsCurrent()`，在更新播放状态、首次播放标记和播放记录之前拒绝旧媒体事件；试听保留原有独立分支。

新增 `scripts/tests/player-media.test.mjs`，通过网页选歌、真实 Chrome 音频解码事件及 HTTP 播放记录接口验证，不调用播放器内部方法，也不人工派发 `playing`。
本地 HTTP 替身先扣住旧歌音频响应，用户选中新歌后扣住新歌解析响应，再释放旧音频，使竞争顺序确定可复现。

- **RED**：仅新增测试时失败，新歌音源尚未返回，页面却显示 `播放中：测试曲1 — Fixture`。
- **GREEN**：加入归属检查后，旧事件不记历史；释放新歌音源后仅写入该歌的一条记录，暂停恢复不重复写入。
- **回归**：全套 `node --test scripts/tests/*.test.mjs` 为 **107/107**（原 106 项 + 1 项隔离浏览器回归）；`git diff --check` 通过。既有测试的临时目录清理在本次运行中定向移入废纸篓，未改测试断言。
- 单独运行：`node --test scripts/tests/player-media.test.mjs`。默认使用本机 Google Chrome，可用 `CHROME_PATH` 指定其他 Chromium 可执行文件。

测试使用独立临时浏览器配置、本地音频及内存接口；配置目录运行后移入废纸篓，不写真实数据库、不访问真实模型或语音服务。原有 39 项冒烟本轮未重跑；真实 Fish 与真实完整串播仍未验证。
