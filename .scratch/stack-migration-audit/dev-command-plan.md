# 一条命令启动开发环境

入口：项目根目录 `npm run dev`。

原则：Vite 负责前端 HMR；Nest 运行编译后的 TypeScript，后端源码修改后编译成功才重启；共享 contracts 先构建，保证首次无产物也能启动。不引入新的运行依赖。

步骤：
1. 先在开发启动器公开入口写集成测试，用临时目录、真实子进程与文件修改验证首次构建、自动重启、失败编译保留旧服务、退出清理。
2. 实现统一进程管理与源码监听，连接根 dev 命令；启动前检查端口，避免连接旧后端或默默换前端端口。
3. Vite 代理与后端共享实际地址；验证测试、类型检查，补启动说明。

按上一轮 TDD 约定，测试经过启动器与进程/文件边界，不替换内部生命周期逻辑。既有用户服务不自动终止。

## 验证结果

- 集成测试先失败（尚无启动器），实现后通过：无初始产物构建、源码变更后替换进程、编译失败保留旧进程、修正后恢复、Ctrl+C 清理前后端。
- 最初使用系统目录 watcher 在当前环境报 EMFILE；改为仅针对后端和共享包源码/配置的 300ms 文件检查，支持文件新增、删除与原子替换。
- 根 `npm run dev` 实测发现旧 Vite 占用 5173，明确提示并退出，没有终止旧进程或启动真实后端。
- `npm test` 完整构建后 146/146 通过；三包 typecheck 通过。
- 实际供应商调用和用户数据库没有参与本轮启动器回归。测试临时目录已移入废纸篓。
