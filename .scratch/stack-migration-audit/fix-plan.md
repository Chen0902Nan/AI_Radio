## 第一性原则

1. 唯一音频出口、唯一浏览器节目队列。追加待播内容不能重置正在播放的媒体。
2. 收听会话、用户播放意图、某次媒体播放是不同身份。暂停保留会话，停止结束会话；新会话不能沿用旧实例的记账与停止状态。
3. 准备成功只表示内容可用；只有队列真正增加才算补歌成功。到货、SSE、异步响应均不得覆盖暂停/停止/较新的意图。
4. 每次真实出声最多记一次播放，结束/跳过/失败/停止关闭同一条记录。迟到的开始响应仍要按它自己的结束原因收尾。
5. SSE 只通知状态；HTTP 是补歌批次的唯一交付方式。事件丢失后查快照，重复、旧会话及旧任务消息不改变播放。
6. 测试必须经过生产使用的公开入口。用假 audio、可控时间、外部 HTTP/事件替身隔离外部系统，不替换内部播放/补歌/DJ 控制器。

## 测试范围与公开入口（沿用已授权审查的复现入口）

- 应用装配：getRadioInstance 暴露的播放命令、队列/应用快照及 HTTP 请求结果。若需要独立实例，将创建函数显式导出，生产单例也调用它。
- 媒体：PlaybackController 的公开命令、audio 事件、队列与快照；不访问私有状态。
- HTTP：真实 Nest Controller/路由响应；替换网易云、Codex、Fish 等外部接入，使用隔离数据库。
- UI：真实 React 渲染的文案/来源链接及浏览器用户动作。
- 工程：根 npm test/build/typecheck 命令与无旧产物条件。

## 实现顺序

每轮只新增一个行为的失败测试，记录 RED，再做对应最小修复并验证 GREEN，不先堆齐全部测试。

1. **补歌闭环**：批次真实追加、阈值随播放重评、去重一致、队尾等待与到货续播；暂停不出声、停止/切来源拒绝迟到批次。
2. **媒体与会话生命周期**：坏歌有界换歌；暂停/停止清理重试；停止后新会话续播并自然衔接；每曲记录与迟到响应收尾。
3. **新计划不打断当前曲**：更新待播列表、作废旧准备机会与过期计划；保持媒体时间及暂停意图。
4. **SSE 与 DJ 展示**：订阅生命周期、首次/重连快照、事件幂等与身份过滤、有界轮询降级；状态、文案、来源链接跟随真实任务。
5. **后端与验证修复**：四类故障注入被实际路由消费；API 不落 SPA；根测试自动准备当前产物并包含播放器及应用测试；启动说明与实际命令一致；稳定性采样能识别非零时间冻结并记录补歌/DJ指标。
6. **收尾**：运行完整相关回归、类型检查、三包构建及隔离 Browser E2E；更新审查状态和证据。真实供应商/两小时验收若本轮未执行，明确保留边界，不把模拟替代真实验收。
